# MODELS.md — модели, лицензии, требования

Источник истины — [`configs/models.yaml`](configs/models.yaml). Этот документ его объясняет.
Расхождение между ними ловит `scripts/check_licenses.py` в CI.

## Ограничения ТЗ

| # | Требование | Как обеспечивается |
|---|---|---|
| C1 | Только открытые веса, лицензия **Apache-2.0 / MIT** | поле `license` в реестре + CI-гейт |
| C2 | LLM/VLM ≤ **35B**, text-to-image ≤ **20B** | поле `params_total_b` + CI-гейт |

CI падает, если хоть одна модель нарушает `constraints` из того же файла. Проверка запускается
и локально: `make gates`.

## Состав

| Роль | Модель | Лицензия | Размер | Где используется |
|---|---|---|---|---|
| `llm_main` | [Qwen/Qwen3-32B](https://huggingface.co/Qwen/Qwen3-32B) | Apache-2.0 | 32.8B | планирование колоды, композиция слайдов |
| `llm_fast` | [Qwen/Qwen3-30B-A3B](https://huggingface.co/Qwen/Qwen3-30B-A3B) | Apache-2.0 | 30.5B (активных 3.3B) | массовая композиция, перегенерация заголовков, запасной путь при превышении бюджета |
| `vlm_judge` | [Qwen/Qwen3-VL-8B-Instruct](https://huggingface.co/Qwen/Qwen3-VL-8B-Instruct) | Apache-2.0 | 8.0B | классификация макетов, контекстуальный аудит |
| `t2i` | [Qwen/Qwen-Image](https://huggingface.co/Qwen/Qwen-Image) | Apache-2.0 | 20.0B | генерация изображений (задача «со звёздочкой») |

## Почему именно так

**`llm_main` — Qwen3-32B.** Упирается в потолок 35B, даёт лучшее качество структурированного
вывода среди доступных открытых моделей и хорошо работает по-русски. Планирование колоды —
один вызов на всю колоду, здесь качество важнее скорости.

**`llm_fast` — MoE 30B-A3B.** При 30.5B общих параметров активны только 3.3B, поэтому
пропускная способность в разы выше при сопоставимом качестве на задачах заполнения схемы.
Это плановый путь деградации по бюджету C5: переключение делается конфигом, без правки
пайплайна (ARCHITECTURE.md §12).

**`vlm_judge` — 8B, а не больше.** Судья вызывается по три раза на слайд (мажоритарное
голосование), то есть 36 вызовов на колоду из 12 слайдов. Модель крупнее не влезает в бюджет
аудита в 60 с. Вопросы формулируются как бинарные, и на них 8B отвечает устойчиво.

**`t2i` — ровно 20B.** Потолок ТЗ для text-to-image. Кандидат на дескоуп первым.

## Системные требования

| Сценарий | GPU | Комментарий |
|---|---|---|
| Полный прогон, `llm_main` | 2 × A100 80GB или 1 × H100 | bf16, vLLM, tensor parallel |
| Полный прогон, `llm_fast` | 1 × A100 80GB | MoE, активных 3.3B |
| Только VLM-аудит | 1 × 24GB (RTX 4090 / L4) | |
| `t2i` | 1 × 40GB | отдельным сервисом |

Инференс поднимается **отдельным сервисом** (vLLM или VK Inference) и общается с приложением
по OpenAI-совместимому протоколу. В образ приложения ни torch, ни vllm не входят: это отдельная
группа зависимостей `inference` в `pyproject.toml`.

Топ-10 использует инференс VK — меняется только `DECKFORGE_LLM_BASE_URL`, код не меняется.

## Structured output

Все вызовы идут через guided decoding по JSON Schema, сгенерированной из доменных моделей
(`schemas/*.schema.json`). Модель физически не может вернуть невалидный `SlideIR`.
При отказе бэкенда — два ретрая, затем деградация до упрощённого макета.

## Что не является моделью

Сознательно решено детерминированно, без LLM:

- орфография — LanguageTool (self-hosted сервер);
- сверка чисел со слайда с исходными материалами — прямое сравнение `SlideIR` и `ContentPackage`;
- выбор типа диаграммы в типовых случаях — правила в `domain/rules.py`;
- метрики текста и детект переполнения — `fontTools`.

Это не экономия, а требование воспроизводимости: детерминированная проверка на одном
и том же слайде всегда даёт один и тот же результат.
