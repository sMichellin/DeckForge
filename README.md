# DeckForge

Сервис автоматической генерации презентаций в стиле **произвольного** шаблона.
Кейс «Цифровой дизайнер презентаций», ЛЦТ 2026.

На вход — незнакомый `.pptx`/`.potx` и материалы (md, docx, pdf, xlsx, csv, картинки).
На выходе — колода нативными объектами PowerPoint в pptx, pdf и html, с отчётом аудита,
за 2–3 минуты на колоду.

Актуальная сборка — ветка `plan-b`, профиль прогона `plan_b`: слайд строится по слайду-примеру
шаблона, который выбран **до** того, как написан текст ([ADR-009](docs/adr/009-example-before-text.md)).

---

## Для организаторов: три незнакомых шаблона

Нужно: шаблон `.pptx`/`.potx` и материалы к нему. Сервис уже поднят на стенде команды:

| | Адрес |
|---|---|
| Интерфейс | <http://46.32.88.170:8541> |
| API (Swagger) | <http://46.32.88.170:8120/docs> |

Свой экземпляр поднимается одной командой — см. [Запуск](#запуск); адреса тогда
<http://localhost:8501> и <http://localhost:8080/docs>.

**У модели один слот: колоды идут друг за другом.** Одна колода — около 2,5 минуты;
три варианта одного шаблона — около 7–8 минут. Новый прогон в это время просто встанет
в очередь.

**Три варианта вёрстки** — одна и та же колода, поданная по-разному (C7 ТЗ):

| Вариант | Для кого | Как подано |
|---|---|---|
| **Плотный аналитический** (A) | читатель без докладчика | максимум фактов на слайд, данные таблицей, порядок по темам |
| **Визуальный нарратив** (B) | выступление со сцены | одна мысль на слайд, крупная визуализация, порядок по драматургии |
| **Executive summary** (C) | руководитель | вывод первым (пирамида Минто), крупные показатели |

### Через интерфейс — один шаблон, один текст, три варианта

1. Откройте интерфейс. В левой панели:
   * **Профиль прогона** → `plan_b`;
   * **Число слайдов** → «Задать» и нужное число, или «Подобрать автоматически»;
   * **Вариант вёрстки** → **«Все 3 сразу — сравнить рядом»**. Или один из трёх:
     «Плотный аналитический», «Визуальный нарратив», «Executive summary»;
   * **снимите** «Спросить меня перед починкой находок» — тогда прогон не остановится
     на выборе исправлений. Если оставить, после аудита появятся находки с превью слайдов:
     отметьте нужные и нажмите «Исправить выбранное» или «Оставить как есть».
2. **«1. Шаблон»** — файл `.pptx` или `.potx`. **«2. Материалы»** — текст (md, docx, pdf)
   и, если есть, таблицы и картинки. Файлы кладутся **один раз** на все три варианта.
3. **«Собрать презентацию»**. При «Все 3 сразу» появятся три вкладки — «Плотный
   аналитический», «Визуальный нарратив», «Executive summary», — в каждой свои стадия
   и время. Страницу можно закрыть: прогоны идут на сервере.
4. В каждой вкладке «Колода собрана» → блок **«Скачать»**: PowerPoint, PDF, HTML. Ниже:
   * **«Лист колоды»** — каждый слайд рядом с примером шаблона, по которому он собран;
   * **«Почему такие слайды»** — выбор примера и причина словами;
   * **«Отчёт прогона целиком»** — аудит, заметки, время стадий.
5. Следующий шаблон — «Начать заново» в левой панели, загрузить новые файлы, п. 2.

### Потоком — три шаблона одной командой

Тот же прогон через API, без браузера: каждый шаблон — во всех трёх вариантах.
Положите каждый шаблон в свою папку, материалы —
в подпапку `materials/`:

```
шаблон 1/  Незнакомый.pptx   materials/ТЗ.md  materials/данные.xlsx
шаблон 2/  Другой.potx       materials/…
шаблон 3/  …
```

и выполните (нужны только `bash`, `curl`, `python3`):

```bash
API=http://46.32.88.170:8120      # или http://localhost:8080 у своего экземпляра
q() { python3 -c 'import sys,urllib.parse; print(urllib.parse.quote(sys.argv[1]))' "$1"; }
for dir in "шаблон 1" "шаблон 2" "шаблон 3"; do
 tpl=$(ls "$dir"/*.pptx "$dir"/*.potx 2>/dev/null | head -1)
 for v in A B C; do                # A — плотный, B — нарратив, C — executive summary
  id=$(curl -sf -X POST "$API/runs" -H 'content-type: application/json' \
        -d '{"profile":"plan_b","variant":"'$v'","target_slides":12,"interactive":false}' \
        | python3 -c 'import sys,json; print(json.load(sys.stdin)["run_id"])')
  curl -sf -X PUT "$API/runs/$id/template?filename=$(q "$(basename "$tpl")")" --data-binary @"$tpl"
  for f in "$dir"/materials/*; do
    curl -sf -X PUT "$API/runs/$id/content/$(q "$(basename "$f")")" --data-binary @"$f"
  done
  curl -sf -X POST "$API/runs/$id/start" > /dev/null
  echo "$(date +%T) $dir, вариант $v → прогон $id"
  until curl -s "$API/runs/$id" | grep -Eq '"state": ?"(done|failed)"'; do sleep 15; done
  for fmt in pptx pdf html; do curl -sf -o "$dir/$v-$id.$fmt" "$API/runs/$id/exports/$fmt"; done
  echo "$(date +%T) $dir, вариант $v → $(curl -s "$API/runs/$id")"
 done
done
```

Колоды лягут в папки шаблонов: `A-<run_id>.pptx`, `B-…`, `C-…` и так же `.pdf`, `.html`;
девять колод — около 23 минут. Нужен один вариант — оставьте в `for v in` одну букву. Отчёт прогона —
`GET /runs/<run_id>/report`, находки аудита — `GET /runs/<run_id>/findings`.

### Через интерфейс — автоматически

Тот же путь, что проходит человек в браузере (загрузка → «Собрать» → лист колоды →
кнопки «Скачать»), проходит Playwright в контейнере — локально ставить ничего не нужно:

```bash
for n in 1 2 3; do
  make ui-e2e URL=http://46.32.88.170:8541 TEMPLATE="шаблон $n/Незнакомый.pptx" \
              CONTENT="шаблон $n/materials/ТЗ.md" NAME=template-$n
done
```

Итог по каждому шаблону — `artifacts/ui-e2e/template-N/`: скачанные колоды, снимки
страницы, `result.json` (`passed: true` — колода готова, три формата скачаны непустыми,
ошибок страницы и консоли нет). Сценарий грузит один файл материала.

## Как это устроено

Шаблон читается как **набор правил**, а не как картинка: палитра, типографическая шкала,
сетка, макеты и их вместимость извлекаются в самодостаточный артефакт `TemplateManifest`.
Дальше генерация не имеет доступа к исходному файлу — только к манифесту.

Из манифеста код считает **дизайн-систему шаблона**: роли цветов и читаемые пары, ступени
типографической лестницы, шаг сетки, компоненты — и **каталог слайдов-примеров** с паспортом
каждого: какие у примера места (текст, число, картинка), сколько знаков держит каждое,
какие группы повторяются рядом. Вне плейсхолдеров у шаблонов стоит почти всё содержимое
примеров (96 % у VK Tech, 91 % у VK WorkSpace, 87 % у VK Education): оформление живёт
в примерах, а не в макетах. Поэтому слайд собирается копией примера, а не по сетке.

Граф прогона (LangGraph, чекпойнты в sqlite — прогон переживает перезапуск):

```
parse_template ─┐
                ├→ plan → assign → compose → fit → render → audit → hitl ─→ export
ingest_content ─┘                     ↑                            │
                                      └──────── fix ←──────────────┘
```

| Узел | Что делает | Модель |
|---|---|---|
| `parse_template` | .pptx → `TemplateManifest` → `DesignSystem` с паспортами примеров; кэш по хэшу файла | VLM размечает спорные макеты |
| `ingest_content` | материалы → `ContentPackage`: факты, числа, таблицы, картинки | — |
| `plan` | `DeckPlan`: состав, порядок, утверждённые заголовки, факты на слайд, вид слайда словами | LLM |
| `assign` | **пример на каждый слайд** — детерминированной функцией, до текста (ADR-009): по виду, по местам, без повторов подряд | — |
| `compose` | текст **под места** назначенного примера: схема ответа своя на каждый слайд, предел знаков — по месту | LLM |
| `fit` | вписывание по настоящему шрифту шаблона, кегль только из его шкалы | — |
| `render` | копия слайда-примера, текст в его места, лишние группы снимаются целиком; цвет — ссылкой на тему | — |
| `audit` | реестр проверок: геометрия, контраст, плотность, целостность, числа из фактов, орфография | VLM-судья — по профилю |
| `hitl` / `fix` | выбор исправлений человеком (или автопочинка) и повторная вёрстка | — |
| `export` | pptx, pdf (LibreOffice), html из одного источника | — |

Слайду, которому пример шаблона не подходит, достаётся путь дизайн-системы: макет по виду
и компоненты, собранные из токенов шаблона. Причина выбора — примера или его отсутствия —
пишется словами в отчёт и видна в UI («Почему такие слайды»).

Языковая модель **никогда не пишет .pptx и не пишет код вёрстки** ([ADR-001](docs/adr/001-llm-to-json-ir.md)).
Она заполняет строгий JSON, который валидируется до создания файла. Номера примера модель
не знает и не называет — это знание о файле. Соответствие фирменному стилю — следствие
архитектуры, а не удачного промпта. Подробности и альтернативы — [ARCHITECTURE.md](ARCHITECTURE.md).

## Запуск

Требуется только **podman** (или docker). Python, Poetry, LibreOffice и шрифты живут в образах.

```bash
cp .env.example .env          # эндпоинт инференса, см. «Где брать инференс»
make image                    # образ приложения
make up                       # API, воркер, UI, Redis, LanguageTool
```

UI — <http://localhost:8501>, API — <http://localhost:8080/docs>.

### Воспроизводимый прогон из командной строки

```bash
podman run --rm -v $PWD:/app:z -w /app localhost/deckforge:dev \
  deckforge generate шаблон.pptx материалы/ \
  --brief материалы/brief.yaml --config configs/profiles/plan_b.yaml --variant all
```

Seed фиксирован в конфиге: повторный запуск даёт тот же результат. Другие команды:

| Команда | Что делает |
|---|---|
| `deckforge design-system шаблон.pptx` | html-страница дизайн-системы шаблона |
| `deckforge audit <каталог прогона>` | аудит готового прогона заново, без модели |
| `deckforge rebuild <каталог прогона> -o <куда>` | колода заново **без модели**: план и текст из чекпойнта, вёрстка, аудит и экспорт — текущим кодом |
| `deckforge checks --list` | реестр проверок аудита |

### Параметры прогона

`configs/default.yaml` и профиль поверх него (`configs/profiles/<имя>.yaml`: флаг `--config`
в CLI, поле `profile` в API, «Профиль прогона» в UI).

| Параметр | По умолчанию | Что делает |
|---|---|---|
| `composition.path` | `legacy`; в `plan_b` — **`by_example`** | путь сборки: пример до текста (ADR-009) или прежний |
| `seed` | 1337 | воспроизводимость (C11) |
| `target_slides` | 12 | **потолок**, а не план: на бедном материале слайдов будет меньше, причина — в отчёте |
| `variants` | A, B, C | профили вёрстки из `configs/variants.yaml` |
| `exports` | pptx, pdf, html | что складывать в `out/` |
| `time_budget_s` | 300 | бюджет C5; при отставании включается рычаг деградации |
| `models.*` | `llm_main`, `llm_fast`, `vlm_judge`, `t2i` | роли из реестра `configs/models*.yaml` |
| `audit.run_semantic` | **`false`** | судья-VLM по картинке слайда |
| `audit.auto_fix`, `audit.max_fix_rounds` | `true`, 2 | витки автопочинки |

Профили: `plan_b` — **сдача**, путь `by_example`; `dev` (быстрая итерация), `demo`, `final` —
на прежнем пути `legacy`.

### Что можно выключить, а что нет

**LLM обязательна для плана и текста**; без `llm_main` прогон падает с понятной ошибкой.
Остальное отключается, и каждое отключение видно в отчёте.

| Что | Как | Что теряется |
|---|---|---|
| Смысловой аудит | `audit.run_semantic: false` — по умолчанию | остаются детерминированные проверки |
| Разметка макетов моделью | не задавать `vlm_judge` | вид макета определяет эвристика |
| Размышления модели | `disable_thinking: true` у роли | ничего; разметка макетов VK Tech 1260 → 13 с, 0 отказов вместо 3 |
| Автопочинка | `audit.auto_fix: false` | находки остаются в отчёте |
| Генерация картинок | не задавать `t2i` | слайды без сгенерированных изображений |

## Разбирается ли дизайн на самом деле

Система могла бы выглядеть универсальной, а на деле держаться на трёх знакомых файлах.
Проверяется это не обещанием.

**1. В коде нет ни одной константы шаблона.** Ни RGB, ни имён гарнитур, ни EMU, ни имён
макетов — гейт C6 (`scripts/lint_no_template_constants.py`) падает, если константа появится.
Кегль — из `manifest.typography_scale`, цвет — ссылкой на слот темы, макет и пример — по **виду**.

**2. Из разных шаблонов извлекается разное.** Одна процедура на шести файлах — шесть
разных дизайн-систем:

| Шаблон | Макетов | Гарнитура | Шкала кеглей, pt | Акцент |
|---|---|---|---|---|
| VK WorkSpace | 15 | Arial | 36 / 23,4 / 14 / 9,1 | `#0077FF` |
| VK Tech | 37 | Arial | 24 / 15,6 / 12 / 7,8 | `#0077FF` |
| VK Education | 30 | Arial | 60 / 39 / 20 / 18 | `#0077FF` |
| Шаблон 2024 | 56 | Cera CY | 32 / 20,8 / 13,5 / 8 | `#2354D6` |
| ЛЦТ 2026 | 22 | Montserrat | 28 / 18,2 / 14 / 7,6 | `#FF0053` |
| sauce-containers | 10 | Calibri | 60 / 24 / 15,6 / 10,1 | `#4472C4` |

**3. Незнакомый шаблон проверяется отдельным гейтом.** `tests/e2e/test_cold_template.py`
собирает колоду на шаблонах из комплекта LibreOffice, которые команда не открывала.

**4. Примеры берутся из этого файла, а не из нашего набора раскладок.** Каталог строится
разбором слайдов-примеров и у каждого шаблона свой. Чего у шаблона нет, того система
не придумывает: закрывающий слайд у шаблона без финала берёт родственный вид, и подмена
названа в отчёте.

## Структура репозитория

```
configs/       конфиг прогона и профили, реестры моделей, оси вариантов, реестр проверок
prompts/       промпты по версиям (C9): system.j2, user.j2, schema.json, meta.yaml
skills/        конфиги шагов воркфлоу по версиям
src/deckforge/
  domain/        Pydantic-контракты между слоями — единственный способ передачи данных
  parsing/       .pptx → TemplateManifest, материалы → ContentPackage
  designsystem/  манифест → DesignSystem: цвета, лестница, сетка, каталог примеров
  planning/      → DeckPlan
  composition/   паспорта примеров, назначение примера (assign), текст под места
  layout/        вписывание текста по шрифту, кегль по шкале
  rendering/     копия слайда-примера и нативные объекты python-pptx
  audit/         реестр проверок, VLM-судья, автофиксы
  export/        pptx / pdf / html
  inference/     клиент LLM/VLM/T2I, guided decoding, кэш ответов
  pipeline/      граф LangGraph, HITL, чекпойнты, пересборка без модели
  api/           FastAPI и воркер arq
frontend/      Streamlit: загрузка, параметры, выбор исправлений, лист колоды, скачивание
```

## Ограничения

Заявленная граница ценится выше незаметно отсутствующей функции. **Известно на 29.09:**

- **У модели на стенде один слот.** Прогоны идут строго по очереди; чужие запросы к тому же
  серверу удлиняют ожидание (29.09 прогон VK Tech ждал модель 1350 с при 136 с работы).
- **Слайд без подходящего примера собирается дизайн-системой** — честно, но беднее примера:
  схемы и выноски из компонентов, а не копия оформления автора (Education — 6 слайдов из 10).
- **Место под число заполняется только числом из фактов.** Если в материале слайда цифр нет,
  место-число не заполняется, и его группа снимается — слайд может выйти пустоватым,
  зато без выдуманных цифр.
- **Финальный слайд у шаблона без вида «финал»** берёт родственный пример; если у того нет
  места под текст, на слайде остаётся только заголовок (Education s10).
- **Смысловой аудит выключен по умолчанию**: на однослотовом сервере судья стоит десятки минут
  на колоду. Детерминированные проверки работают всегда.
- **Разметка макетов без размышления модели** точнее по времени, но её точность на эталоне
  не измерена.
- `SmartArt` — составные компоненты из автофигур, а не OOXML-объект `diagram`: python-pptx
  его не создаёт, а готовый XML даёт нередактируемый объект (ARCHITECTURE.md §10).
- Генерация изображений (text-to-image) — задача «со звёздочкой», не входит в сдачу.
- Интерфейс на Streamlit — сознательный выбор в пользу устойчивости демо.
