# DeckForge

Сервис автоматической генерации презентаций в стиле **произвольного** шаблона.
Кейс «Цифровой дизайнер презентаций», ЛЦТ 2026.

На вход — незнакомый `.pptx`/`.potx` и контент-пакет. На выходе — колода из 10–15 слайдов
нативными объектами PowerPoint, в трёх вариантах вёрстки, с отчётом аудита, за ≤ 5 минут.

---

## Как это устроено в двух абзацах

Шаблон читается как **набор правил**, а не как картинка: палитра, типографическая шкала,
сетка, макеты и их вместимость извлекаются в самодостаточный артефакт `TemplateManifest`.
Дальше генерация не имеет доступа к исходному файлу — только к манифесту.

Языковая модель **никогда не пишет .pptx и не пишет код вёрстки**. Она заполняет строгий
JSON (`SlideIR`), который валидируется до создания файла. Сборку делает детерминированный
рендерер на python-pptx: слайд создаётся на макете из шаблона, текст кладётся в плейсхолдеры,
цвет задаётся ссылкой на тему. Поэтому соответствие фирменному стилю — следствие архитектуры,
а не результат удачного промпта. Подробности и альтернативы — в [ARCHITECTURE.md](ARCHITECTURE.md).

## Запуск

Требуется только **podman** (или docker). Локально ничего устанавливать не нужно:
Python, Poetry, LibreOffice и шрифты живут в образах.

```bash
cp .env.example .env          # укажите эндпоинт инференса
make image                    # собрать образ приложения
make up                       # поднять сервисы: API, воркер, UI, LibreOffice, Redis, LanguageTool
```

UI — <http://localhost:8501>, API — <http://localhost:8080/docs>.

### Воспроизводимый прогон конфиг-файлом

```bash
podman run --rm -v $PWD:/app:z -w /app localhost/deckforge:dev \
  deckforge generate templates/unknown.pptx content/ \
  --brief content/brief.yaml \
  --config configs/profiles/final.yaml \
  --variant all
```

Seed фиксирован в конфиге, поэтому повторный запуск даёт тот же результат.
Другие команды CLI: `parse` (шаблон → манифест), `ingest` (материалы → контент-пакет),
`audit`, `export`, `checks --list`.

### Параметры прогона

Прогон настраивается двумя файлами: `configs/default.yaml` и профилем поверх него
(`configs/profiles/<имя>.yaml`, флаг `--config`). Профиль переопределяет базу поблочно.

| Параметр | По умолчанию | Что делает |
|---|---|---|
| `seed` | 1337 | воспроизводимость (C11); в CLI перебивается `--seed` |
| `target_slides` | 12 | **потолок**, а не план: на бедном материале слайдов будет меньше, и причина попадёт в отчёт |
| `variants` | A, B, C | профили вёрстки из `configs/variants.yaml` |
| `exports` | pptx, pdf, html | что складывать в `out/` |
| `time_budget_s` | 300 | бюджет C5; при отставании включается рычаг деградации §15 |
| `parallel_slides` | 6 | параллельная композиция; сверху ограничена `max_concurrency` бэкенда |
| `models.*` | `llm_main`, `llm_fast`, `vlm_judge`, `t2i` | роли из реестра `configs/models*.yaml` |
| `audit.run_deterministic` | `true` | геометрия, палитра, контраст, плотность — считаются кодом |
| `audit.run_semantic` | **`false`** | судья-VLM по картинке слайда |
| `audit.auto_fix`, `audit.max_fix_rounds` | `true`, 2 | витки автопочинки после аудита |

Готовые профили: `dev` (быстрая итерация — один вариант, без VLM, без автопочинки),
`demo` (живой прогон на видео), `final` (сдача — три варианта, полный аудит).

### Что можно выключить, а что нет

**LLM обязательна для плана и композиции.** Текст колоды сочиняет модель; кода, который
писал бы содержание сам, в проекте нет, и прогон без `llm_main` падает с понятной ошибкой
(`PipelineError: стадия 'plan' требует клиента LLM`). Всё остальное отключается, и каждое
отключение видно в отчёте прогона.

| Что | Как выключить | Что теряется |
|---|---|---|
| Смысловой аудит (VLM-судья) | `audit.run_semantic: false` — **так по умолчанию** | остаются детерминированные проверки; на однослотовом локальном сервере судья стоил 36 мин на колоду при бюджете 5 мин |
| Классификация макетов через VLM | не задавать роль `vlm_judge` в реестре моделей | вид макета определяет эвристика по плейсхолдерам; заметка «классификация макетов: без VLM» уезжает в отчёт |
| Размышления модели | `disable_thinking: true` у модели в реестре | ничего; на локальной сборке Qwen3 это 270 с → 38 с на вызов |
| Автопочинка | `audit.auto_fix: false` | находки остаются в отчёте, но не чинятся |
| Рычаг деградации §15 | не задавать роль `llm_fast` | при отставании от бюджета стадии не на что переключиться |
| Генерация картинок | не задавать роль `t2i` | слайды без сгенерированных изображений (задача «со звёздочкой») |

Реестр моделей выбирается переменной `DECKFORGE_MODELS_CONFIG`: `models.yaml` (HF),
`models.groq.yaml`, `models.ollama.yaml`, `models.openrouter.yaml`, `models.ovh.yaml`,
`models.local.yaml` (llama.cpp на своём сервере).

### Рабочие команды

```bash
make test        # тесты
make lint        # ruff
make typecheck   # mypy
make gates       # гейты ТЗ: лицензии моделей (C1/C2) и отсутствие констант шаблона (C6)
make schemas     # перегенерировать JSON-схемы из доменных моделей
make checks      # показать реестр проверок аудита
```

Холодный шаблон (правило 10 AGENTS.md) проверяется отдельно, в образе с LibreOffice:

```bash
podman run --rm -v $PWD:/app:z -w /app -e PYTHONPATH=/app/src \
  localhost/deckforge:worker pytest -q -m cold tests/e2e/test_cold_template.py
```

## Разбирается ли дизайн на самом деле

Вопрос честный: система могла бы выглядеть универсальной, а на деле держаться
на трёх знакомых файлах. Проверяется это не обещанием, а тремя вещами.

**1. В коде нет ни одной константы шаблона.** Ни RGB, ни имён гарнитур, ни EMU,
ни имён макетов — это гейт C6 (`make gates`, `scripts/lint_no_template_constants.py`),
и он падает, если константа появится. Кегль берётся из `manifest.typography_scale`,
цвет — ссылкой на слот темы, макет — по **виду**, а не по названию.

**2. Из разных шаблонов извлекается разное.** Одна и та же процедура разбора
на шести файлах даёт шесть разных дизайн-систем:

| Шаблон | Макетов | Гарнитура | Шкала кеглей, pt | Акцент |
|---|---|---|---|---|
| VK WorkSpace | 15 | Arial | 36 / 23,4 / 14 / 9,1 | `#0077FF` |
| VK Tech | 37 | Arial | 24 / 15,6 / 12 / 7,8 | `#0077FF` |
| VK Education | 30 | Arial | 60 / 39 / 20 / 18 | `#0077FF` |
| Шаблон 2024 | 56 | Cera CY | 32 / 20,8 / 13,5 / 8 | `#2354D6` |
| ЛЦТ 2026 | 22 | Montserrat | 28 / 18,2 / 14 / 7,6 | `#FF0053` |
| sauce-containers | 10 | Calibri | 60 / 24 / 15,6 / 10,1 | `#4472C4` |

Разными выходят и поля, и направляющие, и набор видов макетов. Поведение системы
меняется вместе с ними: на VK Education заголовок в типичную полосу помещается
семью знаками, на «Шаблоне 2024» — сотней, и предел длины заголовка меряется
по файлу, а не берётся из головы.

**3. Незнакомый шаблон проверяется отдельным гейтом.** `tests/e2e/test_cold_template.py`
собирает колоду на шаблонах, которые команда не открывала: они берутся из комплекта
LibreOffice в образе воркера. Путь «манифест → вписывание → нативный .pptx → .pdf»
проходит на них целиком (4 из 4 на 20.09). Любая правка парсера или композитора
обязана проверяться на холодном шаблоне — правило 10 AGENTS.md.

**Где граница честности.** Классификатор макетов на незнакомом шаблоне ошибается тем
чаще, чем дальше шаблон от типовой разметки: у VK Tech из 37 макетов ни один не опознан
как `bullets` или `chart` — все ушли в `custom`, `title` и `quote`. Колода на таком
шаблоне соберётся, но выбор макета под содержание будет беднее. Это ограничение
классификации, а не разбора: палитра, шкала, сетка и вместимость извлекаются верно.

## Переменные окружения

Полный список — в [.env.example](.env.example). Секретов в репозитории нет.

| Переменная | Назначение |
|---|---|
| `DECKFORGE_MODELS_CONFIG` | какой реестр моделей брать: `models.yaml` (HuggingFace), `models.openrouter.yaml`, `models.ollama.yaml` |
| `DECKFORGE_LLM_BASE_URL`, `DECKFORGE_LLM_API_KEY` | OpenAI-совместимый эндпоинт LLM (vLLM, роутер HF, OpenRouter, Ollama, VK Inference) |
| `DECKFORGE_VLM_BASE_URL`, `DECKFORGE_VLM_API_KEY` | VLM: классификация макетов и аудит-судья |
| `DECKFORGE_T2I_BASE_URL`, `DECKFORGE_T2I_API_KEY` | text-to-image (задача «со звёздочкой») |
| `DECKFORGE_REDIS_URL` | очередь arq |
| `DECKFORGE_LANGUAGETOOL_URL` | сервер проверки орфографии |
| `DECKFORGE_SOFFICE_BIN` | LibreOffice headless для pptx → png/pdf |
| `DECKFORGE_ARTIFACTS_DIR` | куда складывать прогоны и кэш разбора шаблонов |
| `DECKFORGE_PROFILE` | профиль промптов (`prompts/registry.yaml`, закрепление версий) |

## Структура репозитория

```
configs/     конфиги запуска, реестр моделей, оси вариантов, реестр проверок
prompts/     промпты по версиям (C9): system.j2, user.j2, schema.json, meta.yaml
skills/      конфиги шагов воркфлоу по версиям
src/deckforge/
  domain/      Pydantic-контракты между слоями — единственный способ передачи данных
  parsing/     .pptx → TemplateManifest, контент → ContentPackage
  planning/    → DeckPlan (состав и порядок слайдов)
  composition/ → SlideIR (наполнение конкретного макета)
  layout/      вписывание текста, авто-кегль, детект переполнения до записи файла
  rendering/   SlideIR → нативные объекты python-pptx
  audit/       реестр проверок, VLM-судья, авто-фиксы
  export/      pptx / pdf / html из одного источника
  inference/   клиент LLM/VLM/T2I, guided decoding, кэш
  pipeline/    LangGraph-граф, HITL, чекпойнты
schemas/     JSON-схемы контрактов (golden-файлы)
scripts/     CI-гейты и сборка пакета сдачи
docker/      образы приложения и LibreOffice
```

## Где брать инференс

Все провайдеры говорят по протоколу OpenAI, поэтому переключение — это две переменные
окружения и выбор реестра моделей. Код модель по имени нигде не называет.

| Путь | Чем платим | Пригодные по ТЗ модели |
|---|---|---|
| **OVHcloud AI Endpoints** | Qwen3.8-27B бесплатно | 7 пригодных моделей, включая открытую Mistral Small 3.2 24B |
| **Groq** | бесплатно, 8000 токенов/мин | Qwen3.8-27B — 0.3 с на вызов |
| **Локальный Ollama** | ничем | `qwen3:8b`, `qwen3-vl:8b`, без лимитов |
| Роутер HuggingFace | месячный лимит кредитов аккаунта | Qwen3.8-27B, Qwen3-VL-30B-A3B |
| OpenRouter | по токенам, от $0.10 за 1M | Qwen3-VL-8B (та самая из §9.2), Qwen3.8-27B |
| vLLM на своей GPU | железом | любые |

**Бесплатного облачного инференса с пригодными моделями не существует.** На роутере
HuggingFace бесплатных провайдеров 0 из 332 пар модель×провайдер; у OpenRouter
23 бесплатные позиции из 446 — и все это Claude, GPT, Gemini, Grok и GLM: закрытые
веса либо больше 35B, то есть прямая дисквалификация по ТЗ. «Бесплатность» HF — это
месячный лимит кредитов на аккаунт, и он кончается за пару сотен вызовов.

```bash
# локально и бесплатно
ollama pull qwen3:8b && ollama pull qwen3-vl:8b
export DECKFORGE_MODELS_CONFIG=models.ollama.yaml
export DECKFORGE_LLM_BASE_URL=http://localhost:11434/v1 DECKFORGE_LLM_API_KEY=ollama
export DECKFORGE_VLM_BASE_URL=http://localhost:11434/v1 DECKFORGE_VLM_API_KEY=ollama
```

## Ограничения

Раздел заполняется честно и по мере работы — заявленная граница ценится выше незаметно
отсутствующей функции (PLAN.md §2).

**Известно на 20.09:**

- **Смысловой аудит выключен по умолчанию.** На локальном сервере с одним слотом судья-VLM
  стоил 36 минут на колоду из десяти слайдов при бюджете C5 в пять минут. Включается
  профилем (`final`, `demo`); чтобы вернуть его в обычный прогон, нужен либо второй слот,
  либо выборка слайдов вместо сплошной проверки.
- **Заполненность слайда ограничена материалом.** Показатели (`kpi`) появляются там, где
  в исходных материалах есть числа; на текстовом ТЗ без цифр их не будет, и выдумывать
  их код не станет. План заказывает визуализацию, композиция её выполняет, а невыполненный
  заказ попадает в отчёт.
- **Профиль прогона не выбирается через API**: `api/jobs.py` читает `configs/default.yaml`
  без профиля, поэтому из UI недоступны `demo` и `final`. Через CLI профиль работает.
- **Классификация макетов на незнакомом шаблоне** тем грубее, чем дальше шаблон
  от типовой разметки (см. раздел выше).
- `SmartArt` реализуется составными компонентами из автофигур, а не OOXML-объектом
  `diagram`: python-pptx его не создаёт, а инъекция готового XML даёт нередактируемый
  объект, что нарушило бы требование о нативных объектах. Обоснование — ARCHITECTURE.md §10.
- Генерация изображений (text-to-image) — задача «со звёздочкой», плановый кандидат
  на дескоуп при нехватке времени.
- Интерфейс на Streamlit, не Next.js: сознательный выбор в пользу устойчивости демо.
