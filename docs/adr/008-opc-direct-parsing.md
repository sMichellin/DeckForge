# ADR-008. Шаблон разбирается напрямую как OPC-пакет, а не через python-pptx

**Статус:** принято 15.09.2026, **пересмотрено в тот же день** (см. §Пересмотр).
Уточняет ARCHITECTURE.md §4.1.

## Контекст

§4.1 предписывала брать плейсхолдеры через python-pptx, а тему — через lxml. На четырёх
настоящих шаблонах такое разделение оказалось неудобным:

1. **Тема находится по связи мастера.** Тем в пакете две-три; `ppt/theme/theme1.xml` —
   имя файла, а не адрес. В VK WorkSpace единственный мастер ссылается на `theme2.xml`,
   в VK Education второй мастер — на `theme3.xml`.
2. **Порядок мастеров важен.** Палитра колоды — у первого мастера в объявлении
   `presentation.xml`, а не у первого по имени файла.
3. **`viewProps.xml` библиотекой не отдаётся**, а направляющие лежат там.
4. **Пустой мастер.** В VK Tech мастер не содержит ни одного плейсхолдера.

## Решение

Слой `parsing` читает пакет самостоятельно: `zipfile` для частей, `lxml` для XML,
`parsing/package.py` для связей. python-pptx остаётся **только** в `rendering`.

## Пересмотр: проверка форка `power-pptx`

Предположение «библиотека не даёт добраться до темы» проверялось на python-pptx 1.0.2.
Прогон `power-pptx 2.12.0` (MIT, форк, упомянутый в ARCHITECTURE.md §8.3) на тех же
четырёх шаблонах показывает, что **для форка пункты 1 и 2 неверны**:

| Пункт | python-pptx 1.0.2 | power-pptx 2.12.0 |
|---|---|---|
| Палитра темы | нет API | `prs.theme.colors.get(MSO_THEME_COLOR.ACCENT_1)` — совпало с нашим разбором на 4/4 шаблонах |
| Гарнитуры | нет API | `prs.theme.fonts.major/minor` — совпало на 4/4 |
| Тема нужного мастера | нет API | `master.part.part_related_by(RT_THEME)` — корректно даёт theme2/theme3 |
| Геометрия при пустом мастере | — | разрешается, 0 плейсхолдеров без координат на 4/4 |
| Направляющие (`viewProps`) | нет | **нет**: в пакете только константа типа содержимого, API отсутствует |
| Превью слайдов | нет | `prs.render_thumbnails()` — обёртка над headless LibreOffice |

**Вывод: главное обоснование этого ADR не выдержало проверки.** Тема через форк доступна,
и пункты 1, 2, 4 отпадают. В силе остаётся только пункт 3 (направляющие) — этого одного
мало, чтобы писать разбор пакета самостоятельно.

## Что решено делать

**Парсер не переписывается сейчас.** Он реализован, покрыт тестами и проходит на четырёх
настоящих шаблонах; замена работающего слоя ради уменьшения своего кода — не та работа,
которую стоит делать за десять дней до сдачи. Обоснование этого ADR меняется на честное:

> Слой чтения не зависит от библиотеки записи. Это не вынужденная мера, а выбор:
> §8.3 допускает смену библиотеки записи, и при таком разделении смена затрагивает
> ровно `rendering`.

**Форк берётся там, где он даёт то, чего у нас нет.** Change `adopt-power-pptx`:

| Что берём | Вместо чего | Change |
|---|---|---|
| `render_thumbnails()` | своя обёртка над `soffice` | (6) `template-preview-render` |
| писатель pptx | python-pptx 1.0.2 (без релизов с 08.2024) | (13) `pptx-writer` |
| `inherit.resolve_color` | свой резолвер эффективного цвета | (13) |
| `accessibility` (контраст) | своя проверка WCAG | (15) `audit-deterministic` |
| `theme.colors` | — | перекрёстная сверка нашего разбора в тестах |

Направляющие (`parsing/grid.py`) остаются нашими в любом случае.

## Условие пересмотра

Если форк выпустит API к `viewProps` и к каскаду плейсхолдеров с контролем источника
значения, перевести на него и чтение: тогда свой разбор пакета перестанет окупаться.
