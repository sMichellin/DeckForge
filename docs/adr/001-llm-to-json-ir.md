# ADR-001. LLM → строгий JSON-IR → детерминированный рендерер

**Статус:** принято, 15.09.2026

## Контекст

Нужно собрать .pptx нативными объектами по незнакомому шаблону. Модель ≤ 35B должна
участвовать в наполнении, но результат обязан быть валидным файлом с редактируемыми объектами.

## Варианты

| Маршрут | Вердикт |
|---|---|
| HTML/CSS → конвертация в pptx (Marp, Slidev, Reveal) | ❌ конвертеры кладут слайд растром или ломают объекты — прямое нарушение требования о нативных объектах |
| LLM пишет Python-код → песочница (AutoPresent/SlidesLib) | ⚠️ модели ≤ 35B нестабильно пишут исполняемый код вёрстки; нужна песочница и retry-циклы, съедающие бюджет в 5 минут |
| **LLM → JSON-IR → рендерер** | ✅ схема валидируется constrained decoding, ошибка ловится до записи файла, аудит работает по геометрии, результат воспроизводим |

## Решение

LLM **никогда не пишет .pptx и не пишет код вёрстки**. Она производит только `SlideIR` —
Pydantic-модель, схема которой передаётся в guided decoding. Сборку делает детерминированный
рендерер на python-pptx.

## Следствия

- Ошибка модели становится ошибкой валидации до создания файла, а не битым слайдом после.
- Аудит может работать по геометрии, а не только по картинке.
- Рендерер обязан покрывать все нужные виды блоков: чего нет в `SlideIR`, того не будет
  на слайде, как бы модель ни старалась.

## Условие пересмотра

Если на холодном шаблоне рендерер не покрывает более 20 % макетов — включаем маршрут
кодогенерации как fallback для непокрытых случаев (change `codegen-fallback`, №25).
