# ADR-009. Пример выбирается до текста

**Статус:** принято, 28.09.2026; действует с 30.09 за флагом `composition.path`.
Уточняет [ADR-003](003-template-manifest.md) (правка 23.09) и [ADR-006](006-langgraph.md).

## Контекст

С 23.09 слайд собирается так: план называет вид композиции словами, композиция пишет
текст под макет, потом `bind_to_recipe` подбирает слайд-пример счётом мест и раскладывает
по его зонам уже готовый текст. Модель узнаёт о примере только одно число — ёмкость
самой маленькой зоны (`target_chars`).

Прогон 28.09 (`2026-09-28-main-19e3b7e`, три шаблона кейса) показал, во что это обходится:

* ни одному из 24 содержательных слайдов пример не достался по смыслу — у всех путь
  `fitting`, «заказанного вида нет, взят ближайший по местам»;
* один пример занимает до 6 слайдов из 10 (VK Tech, `ex018`);
* текст, не вставший в зоны, снимается или сплющивается: 4 снятых блока, 2 схемы
  в строку текста, 6 слайдов с пустыми карточками на одной колоде.

С 24.09 заведено 35 задач RG, и починенное возвращается: s10, закрытый 26.09, 28.09
снова пустой. Задачи лечат следствия одного порядка шагов: текст пишется раньше, чем
известно, под какие места.

## Рассмотренные варианты

| Вариант | Вердикт |
|---|---|
| Оставить порядок, чинить раскладку (`bind_to_recipe`, удаление лишнего) | ❌ Так шли 24–28.09. Раскладка готового текста по чужим местам всегда что-то теряет, а каждый новый шаблон ломает очередную догадку |
| Модель выбирает пример сама, по номеру | ❌ Нарушает ADR-003: номер примера — знание о файле, модель его не называет |
| **Пример на всю колоду выбирает детерминированная функция до текста, текст пишется под места примера** | ✅ Так же устроен PPTAgent (EMNLP 2025): образец назначается записи плана, и только потом по его схеме пишется содержимое |

## Решение

1. Между узлами `plan` и `compose` встаёт узел `assign`. Он вызывает чистую функцию
   слоя композиции `assign_recipes(plan, catalogue, seed)`: примеры выбираются на всю
   колоду сразу, с учётом соседей и повторов. Причина выбора пишется в `run.json`.
2. Композиция получает схему мест выбранного примера (паспорт) и пишет текст под неё:
   роль и предел знаков каждого места. Раскладка ответа по зонам — копирование, а не подбор.
3. Нет подходящего примера — слайд собирается путём дизайн-системы на макете, а не
   в «ближайший по местам» пример.
4. Запрет ADR-003 сохраняется: модель номер примера не называет. Меняется только
   момент выбора — до текста, а не после.

Порядок вводится за флагом `composition.path` в `configs/default.yaml`:

* `legacy` — прежний путь, значение по умолчанию до приёмки плана Б;
* `by_example` — новый путь. Пока узла `assign` нет, прогон с этим значением
  отказывает при старте, а не уходит молча на старый путь.

## Следствия

- Граф получает узел `assign`. Логика выбора живёт в `composition`, а узел — тонкая
  обёртка (ADR-006). Маршрутизация по флагу — единственное новое ветвление графа.
- Гонка «не два одинаковых подряд» уходит: соседей видит `assign`, а не параллельные
  вызовы `compose`, которые узнают предыдущий пример только после ответа модели.
- Дизайн-система должна описывать места примера (паспорт), а не только его зоны.
  Модель паспорта — контракт между потоками A и B, её фиксируют первой.
- Приёмка — по таблице `docs/agents/tasks-plan-b.md`, а не по числу ошибок аудита.
  После приёмки `by_example` становится значением по умолчанию, `legacy` удаляется
  отдельным change.

## Условие пересмотра

Если на приёмке слайдов с примером по смыслу меньше 18 из 24 или на шаблоне кейса
без примеров снимается хоть один блок, — порядок не помог, и дело не в моменте выбора.
Тогда пересматривается сама опора на слайды-примеры (ADR-003, правка 23.09), а не
порядок шагов.
