# ADR-003. Дизайн-система — отдельный артефакт (`TemplateManifest`)

**Статус:** принято, 15.09.2026

## Контекст

Если генерация имеет доступ к файлу шаблона, она рано или поздно начнёт «подглядывать»:
брать координаты конкретной фигуры, ориентироваться на имя макета. Это и есть заточка
под знакомый шаблон, только незаметная.

## Решение

Парсинг отделён от генерации. Результат парсинга — самодостаточный JSON, кэшируемый
по SHA-256 файла. Генерация **не имеет доступа к .pptx-шаблону**, только к манифесту.

## Следствия

- Обе части тестируются по отдельности: парсер — golden-снапшотами манифеста,
  композиция — на синтетическом манифесте, непохожем ни на один реальный шаблон.
- Повторный прогон на том же шаблоне не тратит бюджет на парсинг.
- Всё, чего нет в манифесте, для генерации не существует. Значит, полнота манифеста —
  ответственность парсера, и пробел в нём виден сразу, а не проявляется как странная вёрстка.

## Условие пересмотра

Если появится задача, где нужно скопировать конкретный объект шаблона «как есть»
(например, обязательные слайды 7–11 питч-колоды) — это делается **вне** генерации,
прямой работой с файлом, и никогда не открывает генерации доступ к шаблону.

## Пересмотр 23.09.2026 — slide-recipes

Принято зонтичное предложение `slide-recipes` (`openspec/changes/slide-recipes/proposal.md`):
слайд-пример шаблона становится «рецептом» в дизайн-системе, и writer копирует его XML
в колоду. Это расширяет условие пересмотра:

- **Генерация по-прежнему не имеет доступа к .pptx.** План и композитор видят только
  каталог рецептов в дизайн-системе (вид, зоны, вместимость) — словами, без координат
  и цветов. Файл шаблона открывает только writer на этапе копирования.
- **Копирование — не «как есть».** Рецепт меняет текст по `zone_id`, удаляет лишние
  повторы и пустые зоны. Это допустимо: модель пишет только `SlideIR` (ADR-001),
  копирует и удаляет фигуры только writer, скопированные фигуры — нативные объекты
  pptx с исходной геометрией (C3).
- **Правило «компонент — параметры, а не XML» пересмотрено.** Для слайдов по рецепту
  рендерер не рисует, а копирует. Параметрические компоненты остаются запасным путём —
  для слайдов без рецепта и шаблонов без примеров.
- **Правила 5 и 6 не нарушаются.** В IR слайда по рецепту нет ни цвета, ни кегля:
  их несёт фигура шаблона. Кегль уменьшается только по шкале шаблона
  (`domain.rules.next_size_down`).

Владельцы: `designsystem/**` — поток A, `rendering/recipe_slide.py` — поток B
(`docs/TEAMWORK.md` §2).
