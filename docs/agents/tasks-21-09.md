# Задания потокам на 21.09 — что улучшать дальше, по литературе

Плотность слайдов выросла: по новой метрике пустой полосы (#95) колода `693d464d54fb`
давала 9 находок из 10, нынешние — 0–1. Дальше — не «больше текста», а качество того,

## Что говорят работы

**Assertion–evidence** ([Penn State](https://www.assertion-evidence.com/),
[исследование понимания](https://writing.engr.psu.edu/ae_comprehension.pdf)): заголовок —
утверждение в одно предложение, тело — **визуальное доказательство** (схема, график,
фото, крупная цифра), а не список. Аудитория такой колоды понимает и запоминает материал
лучше, чем аудитория колоды «тема + буллеты». У нас половина уже есть: заголовки-выводы
с #10, переписывание под рамку с #76–#91. Вторая половина — доказательство — пока одна
схема на колоду.

**AeSlides** ([arXiv:2604.22840](https://arxiv.org/abs/2604.22840)): эстетику вёрстки
раскладывают на **верифицируемые** подзадачи — пустота (карта локальной дисперсии),
столкновения элементов, дисбаланс (эллипс с допуском 0,05 по горизонтали и 0,15
по вертикали) — и используют их как награду. Пустоту и дисбаланс мы взяли в #90 и #95.

**DesignLab** ([arXiv:2507.17202](https://arxiv.org/abs/2507.17202)): рецензент находит
дефекты дизайна, исполнитель правит, цикл повторяется. У нас этот цикл есть (аудит →
починка), но починка умеет двигать и сокращать, а **пересобрать слайд не умеет**.

**Best-of-N с проверяющим** ([arXiv:2502.12123](https://arxiv.org/abs/2502.12123)):
сработало на заголовках в #91 — медиана подрезанных 4 → 0.

## Поток A — доказательство вместо списка

**A5. Визуализаций на колоду — одна.** Assertion–evidence требует доказательства
на каждом содержательном слайде. На `task_desription.md` чисел нет, но перечислений
много: «разобрать / понять / подобрать / сверстать», «инференс, шаблоны, контент, CLI»,
«специалисты по данным, инженер ML». Каждое из них — `smartart` (процесс или просто
плитки), а не буллеты. Нужно: в правилах планировщика — перечисление из трёх–шести
коротких однородных пунктов заказывает схему. Мерить по `run_metrics.py` на трёх прогонах:
«визуализаций» медиана 1 → хотя бы 4.

**A6. Пересборка слайда по находке оформления.** Когда `design.ink_balance` находит
пустую полосу, починке сейчас нечем ответить. По DesignLab — вернуть слайд композитору
с названным дефектом («под текстом пустая полоса в 40 % высоты: дай доказательство
или разложи тезисы шире»). Это новый авто-фикс `recompose_slide`: один вызов на слайд,
только по находкам, поэтому в бюджет укладывается.

## Поток B — вёрстка

**B5. Дисбаланс с допуском по осям, как в AeSlides.** Сейчас смещение центра меряется
одним числом по худшей оси. AeSlides допускает по вертикали втрое больше, чем
по горизонтали: колода читается сверху вниз, и содержание под заголовком естественно
смещено вниз, а перекос вбок — дефект. Нужно: эллиптическая норма с допусками по осям,
пороги откалибровать по тем же шести прогонам.

**B6. Схема «плитки» для перечислений.** Для A5 нужен вид схемы без стрелок — однородные
пункты, а не шаги. В `SmartArtPattern` есть `matrix`, но `layout/diagram.py` его не рисует
(поддержаны process, timeline, cycle). Нужно: раскладка плиток сеткой 2×2 / 2×3 / 3×2.

## Поток C — аудит

**C7. Метрики оформления в отчёт прогона.** Чернила, смещение и пустая полоса сейчас
видны только в находках. Нужно: класть их по каждому слайду в `run.json`, чтобы
`run_metrics.py` сравнивал колоды по оформлению так же, как по заголовкам.

**C8. Профиль метрик по шаблону.** В работе arXiv:2508.19289 семь метрик (пустота,
плотность текста, цветность, гармония, контраст, плотность границ, баланс) не «хороши»
и не «плохи» сами по себе. Честнее мерить не против абсолютных порогов, а против самого
шаблона: превью его макетов дают, как выглядит «родной» слайд этого дизайна.

- **A7. Схема и текст говорят одно и то же.** Рядом с плитками «Парсинг документов,

### Что говорят работы

* **Незаполненная зона макета — известный провал.** SlideTailor
  ([arXiv:2512.20292](https://arxiv.org/html/2512.20292v1)) прямо называет его у PPTAgent:
  «large areas of unreasonable blank space» и оставленные плейсхолдеры шаблона. Лечится
  не вёрсткой, а **выбором макета по схеме содержания**: PPTAgent
  ([arXiv:2501.03936](https://arxiv.org/html/2501.03936v1)) описывает каждый элемент макета
  тройкой «категория, модальность, содержание» и берёт макет, чья схема совпадает
  с тем, что есть у слайда. Текстовому слайду — макет, где текст и есть главный элемент.
* **Модели не видят геометрию по списку плейсхолдеров.** PPTBench
  ([arXiv:2512.02624](https://arxiv.org/html/2512.02624v1)): семантику слайда модели
  понимают на 95 %, а раскладку — нет; маленькую рамку номера слайда принимают за главный
  элемент. Рецепт — давать модели геометрию (JSON с координатами) и рендер вместе.
  Ровно это вскрыл #102: модель не знала, что место высотой в строку.
* **Мерить пустоту и баланс по содержанию, а не по картинке целиком.** AeSlides
  ([arXiv:2604.22840](https://arxiv.org/html/2604.22840v1)) меряет пустоту по карте
  локальной дисперсии (окно 201×151, τ = 0,05) **в двух измерениях**, а дисбаланс —
  эллипсом, где горизонталь строже втрое: x_tol = 0,05, y_tol = 0,15. У нас — только
  строки (пустая полоса) и одинаковый порог по осям. Замер на 1d0bc29cf23f s03: левые 60 %
  пусты, а центр тяжести 0,61 — его тянет вправо логотип шаблона. Пока шаблонный декор
  считается «содержанием», никакой порог этого не поймает.
* **Проверка по рендеру в цикле.** DeepPresenter ([arXiv:2602.22839](https://arxiv.org/pdf/2602.22839))
  и SeaSlides ([arXiv:2608.03298](https://arxiv.org/html/2608.03298)): переполнение,
  перекрытие и пустоту ловят по отрисованному слайду и возвращают агенту как конкретную
  находку; без этого цикла качество заметно падает. Шаблон при этом «владеет вёрсткой»:
  модель выбирает компонент, но не координаты — наш подход (макет + решатель) тот же.
* **Метрики оформления** — [arXiv:2508.19289](https://arxiv.org/html/2508.19289):
  семь дешёвых признаков (пустота, плотность текста, край, баланс, контраст, цвет) плюс
  CLIP и Isolation Forest — плохой слайд как выброс относительно профессиональных.
  Это основа для C8 (профиль метрик относительно шаблона).
