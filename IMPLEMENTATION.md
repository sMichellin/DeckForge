## Этап 1 — понимание шаблона (16–17.09)

### (3) `template-parsing-core` — готово

Файлы: `parsing/package.py`, `parsing/template.py`, `parsing/ooxml/layouts.py`,
`parsing/ooxml/decor.py`, `parsing/capacity.py`, `parsing/layout_kind.py`.

- Пакет читается напрямую как OPC-архив ([ADR-008](docs/adr/008-opc-direct-parsing.md)):
  python-pptx остался только в слое записи.
- Плейсхолдеры — с каскадом `slideMaster → slideLayout`; пустой мастер не ошибка,
  плейсхолдер без геометрии отбрасывается, а не достраивается.
- `capacity` вычисляется из площади и кегля роли.
- Вид макета — по геометрии, с записью уверенности для маршрутизации в VLM.
- Кэш по SHA-256 с инвалидацией по версии парсера.

**Критерий выхода — выполнен:** манифест снимается со всех четырёх настоящих шаблонов
(три от организаторов + шаблон питча), golden-снапшот в `tests/golden/snapshots/`.

### (4) `theme-extraction` — готово

Файлы: `parsing/ooxml/theme.py`, `parsing/typography.py`, `parsing/grid.py`.

- 12 цветов и гарнитуры — из темы **связанного мастера**, а не из `theme1.xml` по имени;
  `sysClr` разрешается через `lastClr`; пустой слот — ошибка, а не значение по умолчанию.
- Типошкала выводится из фактических кеглей плейсхолдеров: `txStyles` мастера в реальных
  шаблонах заполнены одним значением на всех уровнях и шкалы не содержат.
- Направляющие — из `viewProps.xml` (нашлись в 1 шаблоне из 4), иначе кластеризацией
  координат; поля считаются без полноэкранных плашек, иначе обнуляются.

**Критерий выхода — выполнен:** `grid.guides_*` заполнен для всех четырёх шаблонов,
`guides_source` различает `xml` и `inferred`.

### (5) `layout-classification` — готово (кроме замера качества)

Файлы: `parsing/layout_kind.py` (`LayoutClassifier`), `parsing/layout_preview.py`,
`inference/vlm.py` (протокол `VlmClient`), `prompts/layout_classifier/1.0.0/`.

- Эвристика для всех макетов, VLM — только для спорных; при согласии первого вердикта
  с эвристикой остальные прогоны не тратятся.
- Превью — схема из прямоугольников (PIL), без LibreOffice: для определения **вида**
  макета важна структура, а не оформление. Протокол общий с рендером из change (6).
- Кэш по геометрии в долях слайда: одинаковые макеты спрашиваются один раз.
- Ответ вне перечня видов голосом не считается.

Вызовов VLM на настоящих шаблонах (худший случай — когда модель спорит с эвристикой):
VK Tech 16 вместо 63, VK Education 16 вместо 36, ЛЦТ2026 14 вместо 27, VK WorkSpace 0.

**Замеры на живых моделях** (сверка с названиями макетов как с независимым сигналом —
классификатор их не видит):

| Провайдер, модель | Шаблон | Вызовов | Время | Эвристика | +VLM |
|---|---|---|---|---|---|
| OpenRouter, `qwen3-vl-8b` | все четыре | 58 | ~60 с | 27 % | 44 % |
| Groq, `qwen3.8-27b` | VK Education | 14 | 323 с | 40 % | 50 % |

**Причина промахов найдена и устранена.** Схематическое превью рисовало только
плейсхолдеры, поэтому макеты вроде «Паттерн + фото», где картинка лежит обычным `p:pic`,
выглядели пустыми. Теперь `LayoutSpec.shapes` держит фигуры вне плейсхолдеров, схема их
рисует, промпт описывает отдельным разделом «оформление макета, менять нельзя»,
а эвристика их учитывает. Сверка по названиям: VK Education 50 % → 60 %, всего 31 % → 35 %.

Прогон на настоящих шаблонах поймал две регрессии, которых не видно в рассуждении:
фон во весь слайд объявлял фотослайдами 23 макета из 37 в VK Tech, а декоративное фото
на титульном слайде превращало его в две колонки. Обе закрыты правилами, отделяющими
подложку от содержания, и покрыты тестами.

**Планка «≥ 80 %» по-прежнему не достигнута**, и сверка по названиям гейтом быть не может:
на VK Tech она даёт 0 % при любой логике, потому что там полтора десятка разных макетов
называются «Титульный слайд». Нужна ручная разметка одного шаблона.

### (8) `inference-client` — готово

Файлы: `inference/{client,structured,cache,vlm,factory}.py`,
`configs/models{,.openrouter,.ollama}.yaml`.

- Guided decoding по JSON Schema; провайдер без её поддержки обслуживается циклом починки.
- Размышляющие модели: бюджет токенов добирается сам, `<think>` срезается, обрыв при
  запрошенной схеме считается неудачей даже с непустым текстом.
- `InferenceQuotaError` на 402/403 — предохранитель против стука в исчерпанный лимит.
- Кэш по (модель, промпт@версия, seed, запрос) — воспроизводимость C11 и быстрое демо.
- Реестр моделей выбирается `DECKFORGE_MODELS_CONFIG`: HF, OpenRouter или локальный Ollama.

**Бесплатные пригодные модели есть, но не у роутеров-агрегаторов.** У HuggingFace
бесплатных провайдеров 0 из 332, у OpenRouter 23 позиции из 446 и все дисквалифицирующие.
Зато **Groq** раздаёт `qwen/qwen3.8-27b` (apache-2.0, 27.8B, принимает картинки) за
0.3–0.4 с на вызов при лимите 8000 токенов/мин, а **Cloudflare Workers AI** — открытую
`Mistral Small 3.1 24B`, которой сам Mistral через API уже не отдаёт.
Подробности и порядок проверки провайдера — [docs/inference-providers.md](docs/inference-providers.md).
