# Спецификация: слайды по рецептам шаблона

## Задача

Загружаю корпоративный шаблон, а получаю белые слайды с текстом. В шаблоне есть
плашки, цветные подложки, карточки, сочетания цветов, а в колоде от них ничего нет.
Дизайн-система собрана, её видно на отдельной странице, но колоду по ней никто
не верстает.

Причина в коде. Writer удаляет слайды-примеры шаблона и строит каждый слайд из пустого
макета. В этих шаблонах от 87 до 96 % оформления примеров лежит вне плейсхолдеров
макета (замер DS1, `design-system-from-examples`; DS5 — 6–12 % фигур в плейсхолдерах), поэтому пустой макет —
это почти всегда белый фон с рамками под текст. Из дизайн-системы до вёрстки доходят
акцентный цвет, кегль числа, пропорции плитки, полоса цитаты и знак списка. Всё это
срабатывает только на показателях, цитатах, врезках и нумерованных списках.

## Решение

Слайд-пример шаблона становится **рецептом** — готовой композицией, которую автор
шаблона сам собрал: фон, плашки, декор, картинки и текстовые зоны в своих местах,
своими шрифтами и цветами. Каталог рецептов входит в дизайн-систему шаблона новым
разделом «Композиции» и виден на странице дизайн-системы.

Под каждый содержательный слайд подбирается рецепт, который вмещает его содержание.
При записи файла слайд-пример копируется целиком, текст в его зонах заменяется
нашим, лишние повторы (четвёртая карточка при трёх пунктах) убираются. Если
подходящего рецепта нет или у шаблона нет слайдов-примеров, слайд собирается как
сейчас — из макета, с тем, что уже умеет вёрстка по дизайн-системе.

Модель по-прежнему не видит .pptx и ничего не рисует: она получает меню рецептов
словами и пишет текст по зонам, а копирует писатель файла (ADR-003, «Условие
пересмотра»).

**Термин.** *Рецепт* — слайд-пример шаблона, описанный в дизайн-системе как композиция:
номер примера, вид (обложка, перебивка, финал, карточки, показатели, текст с картинкой,
текст), текстовые зоны с ролью и вместимостью, группы повторов, признак картинки.
*Зона* — текстовая фигура рецепта, которую заполняет наш текст. *Повтор* — группа
одинаковых фигур (карточка = плашка + заголовок + текст), найденная по `components`.

## Решения по реализации

0. **Кодовая база** — `sMichellin/slide_write_gen_vid`, ветка `feat/slide-recipes` от
   `origin/main` = `5dcec6f` (23.09). Перед PR — `rebase` на свежий `origin/main`.


1. **Рецепт живёт в дизайн-системе (`designsystem`), а не в доменной модели.**
   Почему: `designsystem` — производная структура, в `schemas/` не едет, её владелец —
   поток дизайн-системы; каталог композиций по смыслу и есть седьмой раздел ДС.
   В домен идут только четыре поля с умолчаниями, без которых нельзя (см. «Запросы тимлиду»).

2. **Вид рецепта выводится из фигур примера, не из имени макета.** Все пороги —
   относительно самого шаблона, ни одного числа шаблона в коде:
   * *область контента* — прямоугольник внутри полей сетки ДС (`grid.margins`);
   * *повтор* — ячейка компонента из `components`, у которого этот пример есть в `seen_on`:
     фигура входит в повтор N, если центр её рамки лежит в N-й ячейке ряда
     (начало ряда + N × шаг, размер ячейки — доли `ComponentSpec`);
   * *крупное число* — текстовая зона, чей кегль ≥ ступени «заголовок слайда» ДС,
     а текст примера короче 8 знаков (`text_len`);
   * *крупная текстовая зона* — зона ступени «тело» или «крупный абзац» с площадью
     ≥ трети области контента.
   Вид: обложка/перебивка/финал — по виду макета примера (`LayoutKind`); иначе повторы
   с крупным числом → «показатели», повторы без числа → «карточки», картинка в области
   контента → «текст с картинкой», крупная зона без повторов → «текст»; первая
   подходящая по этому порядку. Цитата в v1 рецептом не выделяется (признака у фигур
   примера нет) — цитата рисуется как сейчас, по ДС. Пример с диаграммой или таблицей
   в v1 рецептом не становится (Вне рамок).
   *Идентификаторы:* `recipe_id` = `ex<номер примера, три цифры>`, `zone_id` = `z<xml_id>`.
   *Миниатюра на странице* — превью слайдов-примеров, которое уже рендерится для аудита
   (DS7, один рендер на шаблон); нет превью — раздел без миниатюр.

3. **Роль зоны.** Плейсхолдер — роль макета (как сейчас). Свободная фигура —
   по кеглю относительно ступеней типографики ДС: ближайшая ступень даёт уровень
   (`TypeLevel`: заголовок слайда, заголовок карточки, тело, подпись, число). Зона
   внутри повтора помечается номером повтора. Самая крупная зона вне повторов в верхней
   трети слайда — заголовок слайда.

4. **Подбор рецепта: вид выбирает план, конкретный пример — счёт.** Так исполняется
   «план выбирает рецепт под содержание». Меню дизайн-системы, которое план уже получает
   (`design_menu`, #154), пополняется видами рецептов этого шаблона — словами и с числом
   повторов («карточки: 3–4 повтора», «показатели: 3», «текст с картинкой»). План называет
   вид в `suggested_visual` (соответствие значений `suggested_visual` видам — таблица
   в `designsystem.recipes`, одна на все шаблоны). Композиция берёт рецепты этого вида,
   отбрасывает не вмещающие (повторов меньше пунктов, нет зоны под число, картинка без
   ассета), из оставшихся — ближайший по числу повторов, при равенстве — чередование
   по номеру слайда, без одинаковых соседей. Нет рецепта названного вида — любой
   вмещающий, нет и его — прежний путь. Почему не модель выбирает пример: выбор между
   пятьюдесятью слайдами по описаниям модель делает хуже счёта, а номер примера — это
   знание о файле, которого по ADR-003 у генерации нет.
   Рецепты получают и структурные слайды: титул, перебивка и финал берут рецепт вида
   «обложка» / «перебивка» / «финал» — пример на макете того же вида (`LayoutKind`).
   *Содержательный слайд* — любой, чей `intent` не титул, не перебивка и не финал.

5. **Текст по зонам.** Композитор получает у рецепта зоны (роль, вместимость, номер
   повтора) и пишет `SlideIR` с блоками, у которых `zone_id`. Схема ответа модели —
   тот же `SlideIR`, лимиты зон — в промпте из реестра (правило 3).

6. **Копирование — в writer, после композиции.** Writer открывает шаблон, для каждого
   слайда с `recipe_id` клонирует часть слайда-примера (XML + связи: картинки, диаграммы
   делят части с оригиналом), заменяет текст зон с сохранением `rPr` первого прогона,
   удаляет лишние повторы и пустые зоны, подменяет картинку ассетом. Только потом
   удаляет исходные примеры (`_drop_sample_slides`). Слайд без `recipe_id` — как сейчас.

7. **Цвета литералами из шаблона — допустимы.** Прежнее решение
   (`docs/agents/tasks-design-system.md`, «компонент — параметрическое описание, а не
   кусок XML») защищало правило 5: цвет в **IR** — имя слота. При рецепте в IR цвета
   нет вообще: цвет несёт фигура шаблона, которую никто не порождал. Литерал в файле —
   это цвет автора шаблона там, где он его сам поставил. Предложение называет этот
   пересмотр явно, решает тимлид.

8. **Зона узнаётся по `cNvPr id` фигуры**, пример — по номеру в `sldIdLst`
   (`slide_index`, как сейчас) плюс имя части. `shape_id` вида `s000` остаётся для
   обратной совместимости.

9. **Слайд по рецепту — элемент ДС** в `designsystem/usage.py` (`recipe:<вид>`), иначе доля
   «слайдов с элементом ДС» упадёт ровно там, где колода стала выглядеть как шаблон.

10. **Разбиение на changes.** Это предложение — зонтичное: одно решение тимлида на весь
   путь А. Код идёт отдельными changes по волнам (02 контракт, 03 каталог, 04 writer,
   05 план и композиция, 06 конвейер и аудит) — одна capability, одна ветка, один PR
   (AGENTS.md, «Порядок» п.3).

11. **Мерило.** «Слайдов по рецепту, %» в `run.json` и `run_metrics.py`; целевое —
   ≥ 60 % содержательных слайдов на трёх VK-шаблонах, без ухудшения прочих мерил
   (переполнение, контраст, `design.unlike_the_template` — должен улучшиться).

## Границы и швы

| Модуль | Владеет | Выставляет | Прячет |
|---|---|---|---|
| `designsystem.recipes` | каталог рецептов шаблона | `recipes(manifest, ds) -> list[Recipe]`; `Recipe{recipe_id, example_index, part_name, kind, zones: list[Zone], repeats: int, has_picture: bool}`; `Zone{zone_id, xml_id, role: TypeLevel, repeat: int \| None, capacity_chars: int, size_pt}` | вывод вида и ролей, группировку повторов |
| `composition.recipe_picker` | выбор рецепта под слайд | `pick_recipe(slide_plan, recipes, previous: str \| None) -> Recipe \| None` | правила вместимости и чередования |
| композитор (существующий) | текст по зонам | `SlideIR` с `recipe_id` и `zone_id` у блоков | промпт |
| `rendering.recipe_slide` | копирование примера в колоду | `clone_recipe(prs, recipe, slide_ir, content) -> slide` | XML, связи, удаление повторов, подмену текста и картинки |
| writer (существующий) | колода | ветка: `recipe_id` есть → `clone_recipe`, нет → как сейчас | порядок «клонировать → удалить примеры» |

Швы для тестов: `recipes()` на манифесте (синтетическом и трёх VK), `pick_recipe()`
на планах, сквозной `write()` → открытие файла python-pptx + рендер LibreOffice.
Главный шов — `write()` с IR по рецепту: всё видимое пользователю проверяется там.
