Из любого `.pptx` собирается страница его дизайн-системы: семь разделов, открывается двойным кликом без интернета.

```
deckforge design-system "шаблон.pptx" -o дизайн-система.html
```

## Зачем

Сейчас система кладёт текст в плейсхолдеры, и не видно, что она вообще поняла про шаблон. Этот change делает понятое видимым — до того, как по нему начнут верстать. Следующие шаги (роли цвета в композиции, вёрстка слайдов по ДС) опираются на этот слой.

## Что внутри

Новый слой `designsystem` сразу над `domain` — производные шаблона:

- **роли цветов по доле площади**, а не по частоте: подложка на половину слайда весит больше шести подписей
- **сочетания** «фон + текст + акцент», реально встреченные на примерах, с долей и свёрнутым хвостом
- **контрасты WCAG** парами «текст на фоне», считаются готовыми `domain.rules`; пара из темы, не прошедшая AA, помечается риском
- **лестница типографики из восьми уровней**: что есть в шаблоне — `MEASURED`, недостающее достроено из `size_ladder_pt` — `DERIVED`
- **гарнитуры по факту** отдельно от объявленных темой — на трёх шаблонах кейса это расходится
- **достройка** плашек, трёх стилей списков, разделителей, пагинации, таблицы, цитаты и callout **из примитивов шаблона**: цвет слотом темы, кегль из типошкалы, отступ и радиус долями шага сетки

`export/design_system_page.render(ds) -> str` рисует страницу: литеральные цвета только в `:root`, разметка через `var(…)`, внешних ссылок ноль, два вызова дают побайтно равный html.
