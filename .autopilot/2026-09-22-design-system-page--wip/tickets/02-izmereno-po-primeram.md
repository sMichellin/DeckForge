## Что должно заработать

`derive` начинает заполнять измеряемую часть дизайн-системы: какие цвета в шаблоне
какую роль играют, в каких долях, какими сочетаниями, что из этого читается по WCAG
и каким шрифтом шаблон набран на самом деле.

Это то, чего сегодня в проекте нет ни в каком виде: `usage.palette` считает частоту
(«сколько раз встретился»), а роль цвета определяется его **площадью**.

## Что именно строится

**Доли площади.** Для каждого слайда-примера площадь фигуры — `cx × cy`; цвет фигуры
берётся из `fill_hex`/`fill_ref`, цвет её текста — из `color_hex`/`color_ref`.
Непокрытая фигурами площадь отходит фону макета (`LayoutBackground` того макета,
на котором стоит пример). Доли считаются по сумме площадей всех примеров и нормируются
к 100 %.

**Роли.** Первый по доле — фон, второй — доминанта, дальше акценты и редкие. Акцентом
считается цвет насыщенный (различие каналов RGB заметное), а не серый: серый с долей 4 %
— это разделители и подписи, а не акцент. Порог, по которому цвет уходит в «редкое»,
задаётся одной константой в модуле и объясняется комментарием — это **не** константа
под конкретный шаблон, а порог алгоритма, как 2,5 % допуска в `parsing/components.py`.

**Хвост.** Цвета, покрывающие 95 % площади, показываются по отдельности; остальные
сворачиваются в одну запись «ещё N оттенков» с суммарной долей. У VK Tech девятнадцать
литералов — без свёртки раздел превращается в простыню.

**Сочетания.** Для каждого слайда-примера: фон + самый крупный по площади цвет текста
на нём + самый заметный цвет заливки, не совпадающий с фоном. Одинаковые тройки
складываются, доля — по числу слайдов. **Сценарий словами не называется** — это была бы
интерпретация, а Настя выбрала «только измеренное». Называются роль, доля и номера
слайдов, где сочетание встречено.

**Контрасты.** Пары «текст на фоне» из слотов темы и из встреченных сочетаний.
Считать через `domain.rules.relative_luminance`, `contrast_ratio`, `meets_wcag_aa` —
своей формулы не заводить, она там уже есть и проверена. Каждая пара получает отметку:
проходит AA, проходит только для крупного текста, или проваливает. Пара, которая
проваливает и при этом взята из самой темы шаблона, помечается как риск, а не прячется.

**Предупреждение про акцент в длинном тексте.** Акцент, который не проходит AA как текст
на светлом фоне шаблона, помечается: годен для графики и крупных меток, не для абзаца.

**Гарнитуры по факту.** Из `manifest.usage.fonts`: семейство, доля знаков, где
встречается — в заголовках, в теле. Отдельно от объявленных в теме: тема называет одно,
примеры набраны другим (у всех трёх шаблонов кейса это расходится).

**Размеры для чисел.** Три размера — крупный, средний, мелкий. Крупный берётся из
`components` вида `kpi` (`text_sizes_pt`, старший кегль), остальные — ближайшие вниз
по `manifest.size_ladder_pt`. Нет KPI-компонента — берутся три верхних кегля шкалы
и помечаются `derived`.

## Критерии приёмки

- [ ] Доли по площади считаются на всех трёх шаблонах кейса, сумма — 100 % ± 0,5
- [ ] Роли назначены: есть фон, есть доминанта, есть хотя бы один акцент там, где он в шаблоне действительно есть
- [ ] Серый цвет с малой долей не попадает в акценты
- [ ] Хвост свёрнут: на VK Tech отдельных цветов не больше десяти, остальные в одной записи
- [ ] Сочетания собраны тройками, у каждого доля и номера слайдов
- [ ] Контрасты считаются через `domain.rules`, у каждой пары отметка AA / AA large / провал
- [ ] Пара из темы, проваливающая AA, помечена как риск
- [ ] Акцент, непригодный для длинного текста, помечен
- [ ] Гарнитуры по факту отделены от объявленных в теме
- [ ] Три размера для чисел заполнены и помечены правильным происхождением
- [ ] Шаблон без примеров: измеряемые поля пусты, `derive` не падает
- [ ] Тесты на шве `derive`, каждый критерий — своим тестом, на настоящих шаблонах кейса
- [ ] `ruff`, `mypy`, `lint_no_template_constants.py` — чисто; полный `pytest` зелёный
