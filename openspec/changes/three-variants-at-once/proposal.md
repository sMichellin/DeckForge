# three-variants-at-once — три варианта из одной загрузки

План Б, круг 3. Запрос владельца 29.09: «в интерфейсе добавить один шаблон и один текст
и получить три варианта — Плотный аналитический, Визуальный нарратив, Executive summary».
Файл `frontend/app.py` — зона потока C; правка по поручению владельца, C предупреждён.

## Explore

Требование C7 ТЗ — три варианта вёрстки. Сервис держит правило «один прогон — один вариант»
(`api/schemas.py::RunRequest`: у каждого варианта свой чекпойнт и своя остановка на выборе
фиксов). Интерфейс же давал выбрать один вариант, и три колоды требовали трёх загрузок одних
и тех же файлов.

## Propose

Сервис не меняется. В интерфейсе:

* в «Варианте вёрстки» последний пункт — «Все 3 сразу — сравнить рядом»;
* `send` создаёт прогон на каждый вариант, загружает в каждый те же файлы и запускает;
* результат — вкладки по названиям вариантов; в каждой прежний вид прогона: прогресс,
  выбор фиксов, лист колоды, скачивание. Ключи виджетов — с номером прогона, чтобы кнопки
  трёх вкладок не спорили;
* страница перерисовывается, пока идёт хоть один прогон.

Прогоны ставятся в очередь сразу: воркер берёт два одновременно (`max_jobs`), у модели один
слот — запросы встают к нему в очередь, три колоды выходят примерно за 3 × 2,5 минуты. Закрыть
страницу можно: прогоны идут на сервере.

## Verify

`tests/unit/test_three_variants_at_once.py`: «все сразу» — каждый вариант (норма); один шаблон
и один текст дают три прогона с теми же файлами и стартом после загрузки (норма); один
вариант — один прогон (нарушитель прежнего вида); переключатель предлагает «все сразу»,
страница без сервиса не падает. Глазами — внешний UI стенда plan-b.

## Что осталось незакрытым

* Номера прогонов живут в сессии браузера: перезагрузил страницу — вкладки пропали, колоды
  остались на сервере (`GET /runs/<id>/exports/<fmt>`).
