# service-api

Change (23), первая половина. Capability: `service-api`. Поток C.
Вторая половина — `web-ui` (Streamlit) — отдельным change: один change = одна capability
(TEAMWORK.md §3).

Статус: proposed → applied

## Explore

`api/app.py` поднимал `NotImplementedError`, `api/worker.py` был классом с пустым списком
функций. При этом `docker/compose.yaml` уже поднимал три сервиса против этих имён —
`uvicorn deckforge.api.app:create_app --factory`, `arq deckforge.api.worker.WorkerSettings`
и Streamlit против `frontend/app.py`. То есть контракт транспорта был задан заранее,
и менять его было нельзя.

В `pipeline` при этом не хватало ровно одного: **возобновления**. `generate_variant`
всегда начинает с `initial_state`, а HITL-остановка требует второго входа в тот же
`thread_id` с `Command(resume=…)`. Без него «выбор пользователя» упирался в тупик:
граф останавливался, и продолжить его было нечем.

## Propose

### Файлы — в хранилище прогона, очередь — для одного сообщения

Через очередь ходит «начни этот прогон» либо «продолжи с таким выбором». Всё остальное —
шаблон, материалы, превью, экспорт, чекпойнт — это файлы, которые всё равно лежат
на диске; копия в Redis была бы вторым источником истины. Каталог прогона монтируется
и в приложение, и в воркер, поэтому статус, написанный воркером, читается приложением
без посредника.

Побочная выгода важнее экономии: **после падения Redis прогон остаётся на диске целиком**,
с отчётом, превью и файлами. Разбирать его можно руками, а не по логам.

### Две очереди, и вторая — не костыль для тестов

`ArqQueue` — рабочий путь: воркер отдельным контейнером, потому что рендер превью
запускает `soffice` подпроцессом и в соседний контейнер не дотянется.

`InlineQueue` гоняет тот же прогон в процессе приложения, без Redis и без воркера. Это
нужно там, где лишний движущийся узел дороже изоляции: **на записи демо (A4)**, где
«без монтажных склеек» означает, что упасть не должно ничто, и при разборе прогона руками.
Ограничения названы в самом классе: перезапуск процесса убивает задачу, параллельные
прогоны делят один цикл событий.

### Загрузка телом, а не формой

`multipart/form-data` в FastAPI требует `python-multipart`, которого в зависимостях нет.
Тащить зависимость (а значит, править `pyproject.toml` — файл тимлида) ради формы, когда
на запрос загружается ровно один файл, незачем: `PUT` с телом описывает то же самое.

### Создание, загрузка и старт разделены

Приложение не может угадать, догрузит пользователь ещё один файл материалов или уже нет.
`POST /runs/{id}/start` — его слово. Заодно старт проверяет, что грузить было что:
прогон без шаблона не уезжает в очередь, чтобы не падать там, где пользователь его не видит.

### Превью ищется по указателю, а не по имени слайда

Рендер именует страницы `deck-1.png`, `deck-2.png`, а находки знают только `slide_id`:
после `split_slide` номера страниц и слайды расходятся, и это не совпадение имён,
а разные системы счёта (`audit/preview.py`). Поэтому воркер пишет рядом с превью
указатель `slide_id → имя файла`, а собрать путь из `slide_id` нельзя в принципе.

Находке при этом добавляется `bbox_rel` — рамка в долях слайда. Пересчёт EMU в пиксели
требует размера слайда; знает его манифест, а манифест до интерфейса не доезжает
и доезжать не должен. Доля — наименьшее, чего достаточно для подсветки, и она
не устаревает при смене масштаба картинки.

### Идентификаторы из URL проверяются, а не чистятся

`run_id` и `slide_id` приходят из URL и участвуют в путях. `run_id` выдаём мы сами —
значит, он обязан быть шестнадцатеричным, и всё прочее отвергается. Имя файла превью
не собирается из `slide_id` вовсе: оно **ищется среди существующих**, и подставить в путь
нечего в принципе. Чистка («выкинем точки и слэши») всегда что-нибудь пропускает.

### Один прогон — один вариант вёрстки

Три варианта это три прогона: у каждого свой чекпойнт, своя остановка на выборе фиксов
и свой отчёт. Пакетная выдача девяти колод (A3) — работа CLI, где человека в середине нет.

### Требования

**Требование: прогон не стартует без материалов.** Сервис SHALL отказывать в старте,
пока не загружены шаблон и хотя бы один файл материалов.

- **WHEN** загружен только шаблон
- **THEN** старт отвечает 409
- **AND** задача в очередь не ставится

**Требование: выбор фиксов возвращается в граф.** Сервис SHALL принимать выбор только
у прогона, остановленного на `hitl`, и передавать его в очередь списком `finding_id`.

- **WHEN** прогон остановлен и человек выбрал находку
- **THEN** задача возобновления уходит в очередь с этим списком
- **WHEN** прогон ещё идёт
- **THEN** выбор отвергается с 409

**Требование: чужая находка не отбрасывается молча.** Сервис SHALL отвергать выбор,
содержащий `finding_id`, которого он не предлагал.

- **WHEN** в выборе есть неизвестный идентификатор
- **THEN** ответ 400, и в очередь не уходит ничего

**Требование: прогресс не выдумывается.** Статус SHALL показывать долю **завершённых**
стадий, без оценки того, сколько осталось внутри текущей.

**Требование: отдаются только объявленные форматы.** Сервис SHALL отдавать файлы по
`exports` из отчёта прогона и только для `pptx`, `pdf`, `html`.

- **WHEN** запрошен `sqlite`
- **THEN** ответ 404, и чекпойнт наружу не уходит

## Что осталось незакрытым

1. **Интерфейса нет — это вторая половина change (23).** `frontend/app.py` не написан,
   compose поднимает Streamlit против несуществующего файла. Пока API дёргается руками
   или из CLI. Следующий PR.

2. **Живого прогона через API не было.** Тесты покрывают транспорт: маршруты, хранилище,
   очередь. Что `run_job` доводит колоду до конца, проверяется только тем, что он зовёт
   `generate_variant`, у которого свои тесты. Нужен прогон с Redis, LibreOffice и моделями —
   на моей машине нет ни одного из трёх.

3. **Правки в файлах тимлида.** `pipeline/run.py` и `pipeline/__init__.py` — добавлены
   `resume_variant`, `RunResult.pending_findings` и `thread_id`. Все три аддитивные,
   поведение существующих функций не изменилось. Без них HITL из API невозможен, а разбор
   `__interrupt__` пришлось бы делать в транспорте — то есть научить API форме объектов
   LangGraph, чего ARCHITECTURE.md §3 прямо не велит.

4. **Прогресс откатывается назад на витке починки.** Граф возвращается на `fit`, и доля
   пройденных стадий честно падает. Это не ошибка отображения, но интерфейсу придётся
   объяснить это человеку, иначе выглядит как сбой.

5. **Аутентификации нет.** Кто угодно, кто дотянулся до порта, может создать прогон,
   скачать чужой экспорт и удалить... нет, удалить не может — метода нет. Для стенда
   на защите это приемлемо, для чего-то большего — нет, и это должно быть заявлено,
   а не подразумеваться.

6. **minio из compose не используется.** Файлы лежат на смонтированном томе. Заводить
   S3 ради одной машины незачем, но если воркеров станет несколько на разных хостах,
   общий том исчезнет — и тогда `RunStore` придётся переносить на S3. Раскладка путей
   собрана в одном классе именно ради этого.

7. **Очередь не знает про отмену.** Начатый прогон нельзя остановить: `DELETE /runs/{id}`
   не заведён. Для пятиминутного прогона терпимо; на девяти колодах уже нет.
