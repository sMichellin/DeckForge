# the-ui-is-checked-end-to-end — сдача проверяется через интерфейс

План Б, круг 3, задача тимлида 2 (`docs/agents/tasks-plan-b-round-2.md`). Ветка от `plan-b`
(`bebc46b`). Файлы: `scripts/ui_e2e.py`, `Makefile` (цель `ui-e2e`) — зона тимлида.

## Explore

Приёмка плана Б шла через API (`run-plan-b.sh` на стенде): API отдавал pptx, pdf и html.
Сдача же принимается через UI — человек кладёт файлы, жмёт «Собрать» и скачивает колоду.
29.09 этот путь впервые прошёл Playwright через внешний адрес стенда (http://46.32.88.170:8541),
сценарий жил во временном каталоге. Он нашёл то, чего API не видит:

* поле «Адрес сервиса» снаружи показывает `localhost:8120` (задача C1);
* пустые слайды s01, s10 на листе колоды (задача A1);
* прогон VK Tech ждал модель 1350 с — первый вариант сценария ждал 600 с и сдался.

Прогон WorkSpace `a3a8f3a2319b`: «Колода собрана» за 122 с, скачаны pptx 9,5 МБ (10 слайдов),
pdf 0,7 МБ (10 страниц), html 15 КБ, ошибок страницы и консоли нет.

## Propose

Сценарий — в `scripts/ui_e2e.py`, запуск — `make ui-e2e` в официальном образе Playwright.
Playwright **не** добавляется в зависимости проекта (правило 8): он нужен только проверке,
и образ `mcr.microsoft.com/playwright/python` уже несёт браузер. Скрипт импортирует Playwright
внутри `run`, чтобы его решения (когда прогон кончился, что считается сдачей) тестировались
без браузера.

Сдача через UI = колода готова ∧ pptx, pdf, html скачаны непустыми ∧ ошибок страницы
и консоли нет. Ожидание по умолчанию — 1800 с: слот модели общий.

## Verify

`tests/unit/test_the_ui_is_checked_end_to_end.py` — нормы и нарушители на каждое решение.
Живой прогон — на стенде plan-b, WorkSpace: `passed` ожидается `false` до C1 (адрес сервиса).

## Что осталось незакрытым

* Сценарий завязан на подписи страницы («Собрать презентацию», «Скачать», «Лист колоды»):
  смена текста в `frontend/` сломает его. Устойчивее — `data-testid` на элементах, это задача C.
* В CI прогон через UI не входит: ему нужен стенд с моделью.
