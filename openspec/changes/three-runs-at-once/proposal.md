# three-runs-at-once — варианты «все сразу» идут одновременно

План Б, круг 3. Запрос владельца 29.09 после #292: «Плотный аналитический и Визуальный
нарратив генерились сразу, а Executive summary ждал в очереди — можно ли все три параллельно».
Файлы: `src/deckforge/config.py` (тимлид), `src/deckforge/api/worker.py` (зона C — по поручению).

## Explore

Воркер arq вёл два прогона (`max_jobs = 2`, зашито в код). Прогон «Все 3 сразу» 29.09
(`4ef530f40281`, `dacd9992ba80`, `06af35f86a23`): A и B шли вместе, по 253–255 с каждый
(один — около 150 с: делили слот модели), C стартовал через 4 минуты и шёл 248 с. Всего 538 с.

Модель на стенде — один слот. Время колоды на 80 % — `plan` и `compose` (195–224 с
из 250), то есть очередь к модели. Три параллельных прогона суммарно быстрее не станут:
модель пройдут по очереди те же запросы. Выигрыш — в том, что видит человек: все три
вкладки идут, ни одна не стоит «в очереди». Память стенда — 26 ГБ свободно, 32 ядра.

## Propose

`Settings.worker_max_jobs` (`DECKFORGE_WORKER_MAX_JOBS`), по умолчанию 3 — по числу
вариантов; `WorkerSettings.max_jobs` берёт его. На машине с малой памятью — переменной.

## Verify

`tests/unit/test_three_runs_at_once.py`. Живой прогон «Все 3 сразу» через UI стенда:
три прогона в состоянии «идёт» одновременно, время колод.

## Что осталось незакрытым

* Быстрее колоды не станут, пока у модели один слот: это настройка сервера llama.cpp
  (`--parallel`), а не наша.
* Запрос модели ждёт в её очереди дольше, когда прогонов три: при таймауте 300 с на вызов
  запас есть (план — до 70 с, слайд — 10–20 с), но под чужой нагрузкой он меньше.
