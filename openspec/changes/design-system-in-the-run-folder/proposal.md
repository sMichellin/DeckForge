## Explore

Заметка к прогону 26.09: «Нет отдельного файла с дизайн-системой в папке, чтобы
проверить».

Страница дизайн-системы собирается только отдельной командой
`deckforge design-system <шаблон>` (`export/design_system_page.py`). Узел `export`
её не пишет, хотя дизайн-система уже лежит в состоянии графа (`state["design_system"]`,
DG2) и по ней собрана колода. В `run.json` — только сводки чисел: `design_system`
(размеры разделов) и `design_system_usage` (что из ДС стоит на слайдах). Проверить,
**какая** палитра, шкала и каталог композиций легли в основу колоды, можно только
повторив разбор шаблона вручную.

## Propose

1. Узел `export` после форматов колоды пишет в папку прогона:
   * `design-system.html` — страницу той же функцией `render`, что у команды: на одном
     шаблоне они совпадают;
   * `design-system.json` — саму `DesignSystem`: её можно сравнивать программой.
2. Пути — в новом поле состояния `design_system_files` и в `run.json` под тем же ключом.
   Не в `exports`: там форматы колоды, которые API отдаёт на скачивание по белому списку
   (`api/app.py`, `EXPORT_TYPES`), и интерфейс их перебирает фиксированным списком.
3. Не записалось — названо в `errors`, колода остаётся: тот же принцип, что у html
   (`export-node-does-not-lose-the-deck`).

Скачивание страницы из интерфейса — не здесь: это `api/**` и `frontend/**`, поток C,
отдельным change'ем, если понадобится.

## Проверка

`tests/unit/test_design_system_in_the_run_folder.py` — сквозной прогон графа на подделке
модели: в папке вывода оба файла, `run.json` называет пути, страница совпадает с командой
на том же шаблоне, JSON читается обратно в ту же `DesignSystem`; сборка страницы
с исключением — колода на месте, ошибка названа.

Попутно: `pipeline/run.py` на `main` не проходил `ruff check` (порядок импортов `I001`,
обе версии ruff) — поправлено, раз файл всё равно правится.
