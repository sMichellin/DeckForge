# slide-recipes

**Зонтичное предложение**: одно решение тимлида на весь путь А. Своей capability у него нет,
кода в нём нет. Код идёт отдельными changes по волнам, и у каждого своя capability, ветка
и PR (AGENTS.md, «Порядок» п.3). Их список — в разделе «Changes по волнам».

Основание: прогон 23.09 — «презентации получаются просто белый слайд и текст… агенты никак
не работают с дизайн системой» (R02). Дизайн-система собрана и видна на своей странице,
но колоду по ней никто не верстает. Нужно, чтобы вёрстка брала из шаблона «все компоненты,
плашки, цвета, шрифты, сочетание плашек — как всё используется в шаблоне».

Статус: предложено, ждёт решения тимлида (23.09). Ветка предложения `feat/slide-recipes`.
Код не пишется до «ок» по этому предложению: путь А задевает `domain/**`, `schemas/**`,
`parsing/**`, `pipeline/**` (тимлид) и файлы всех трёх потоков — список ниже.

**Путь А выбрала Настя** (владелец продукта): копировать слайды-примеры шаблона. Честные
следствия:

* слайды без подходящего рецепта и колоды на холодных шаблонах (без примеров) собираются
  как сейчас. При цели 60 % до 40 % содержательных слайдов колоды может остаться «белым
  слайдом с текстом». Путь Б — рисовать плашки из компонентов ДС на пустом макете — это
  следующий change;
* **сужение просьбы «все компоненты»**: примеры с диаграммами и таблицами, а также цитаты
  в v1 рецептами не становятся. Такие слайды идут прежним путём.

## Explore

**Почему слайды белые.** Writer открывает шаблон и первым делом удаляет все слайды-примеры
(`rendering/writer.py:457` → `_drop_sample_slides`, `writer.py:112`), а каждый слайд колоды
строит из пустого макета: `prs.slides.add_slide(layout)` (`writer.py:513`). Но оформление
шаблона живёт не в макетах. Замер DS1 (`openspec/changes/design-system-from-examples/proposal.md`,
таблица замера; то же в `docs/agents/tasks-design-system.md:65`):

| | VK Tech | VK WorkSpace | VK Education |
|---|---|---|---|
| Содержимое примеров вне плейсхолдеров | 96 % | 91 % | 87 % |

То же с другой стороны показал DS5 (`layout-from-the-template-examples`): из содержательных
фигур примеров в плейсхолдерах стоят 6–12 %. Автор шаблона рисует слайд фигурами поверх почти
пустого макета. Пустой макет — это белый фон с рамками под текст, и никакая «вёрстка по ДС»
поверх него плашек автора не вернёт.

**Что из дизайн-системы доходит до вёрстки сейчас** (`layout/by_design.py`, докстринг модуля):
акцентный слот, кегль числа (`number_sizes`), пропорции плитки (`components`), полоса
и отбивка цитаты и callout, знак нумерованного и иконочного списка, шаг между блоками.
Всё это срабатывает только на показателях, схемах, цитатах, врезках и особых списках.
Абзац и маркированный список — основная масса текста колоды — элементом ДС не считаются
вовсе, их оформляет макет (`designsystem/usage.py:10`). Фона, плашек, декора и их сочетаний
из примеров в колоде нет ни на одном слайде.

**Чего не хватает в манифесте, чтобы взять пример целиком.**

* `ExampleShape.shape_id` синтетический — `f"s{z:03d}"` по порядку обхода
  (`parsing/ooxml/examples.py:166`). Настоящего `cNvPr id` фигуры нет, найти её в XML
  при копировании не по чему.
* Текст фигуры не сохраняется — только `text_len` (`examples.py:175`). Этого хватает:
  копировать мы будем XML примера, а в манифесте нужен лишь размер зоны и кегль.
* `TemplateExample` знает `slide_index` и `layout_id` (`domain/template.py:337`), но не имя
  части. `slide_index` — это позиция в `sldIdLst` (`parsing/template.py:379`,
  `parsing/package.py:126`), а не номер `slideN.xml`, хотя описание поля говорит обратное.
  Опираться на порядок при копировании хрупко.
* `SlideIR` (`domain/slide.py:224`) не ссылается на пример, а текстовые блоки — на фигуру
  примера. Writer не узнает, что копировать и куда писать текст.

## Propose

Слайд-пример шаблона становится **рецептом** — готовой композицией, которую автор шаблона
собрал сам: фон, плашки, декор, картинки и текстовые зоны на своих местах, своими шрифтами
и цветами.

* *Рецепт* — пример, описанный в ДС как композиция: номер примера, вид (обложка,
  перебивка, финал, карточки, показатели, текст с картинкой, текст), текстовые зоны с ролью
  и вместимостью, группы повторов, признак картинки. `recipe_id` = `ex<номер, три цифры>`.
* *Зона* — текстовая фигура рецепта, которую заполняет наш текст. `zone_id` = `z<cNvPr id>`.
* *Повтор* — группа одинаковых фигур (карточка = плашка + заголовок + текст), найденная
  по ячейкам компонента из `components`, у которого этот пример есть в `seen_on`.

1. **Каталог рецептов — седьмой раздел ДС «Композиции»** (`designsystem.recipes`):
   `recipes(manifest, ds) -> list[Recipe]`. Вид выводится из фигур примера, а не из имени
   макета: обложка / перебивка / финал — по `LayoutKind` макета примера; иначе повторы
   с крупным числом — «показатели», повторы без числа — «карточки», картинка в области
   контента — «текст с картинкой», крупная текстовая зона — «текст». Все пороги —
   относительно самого шаблона (поля сетки, ступени типографики ДС, доля области контента).
   Примеры с диаграммой или таблицей в v1 рецептами не становятся.
2. **Роль зоны**: плейсхолдер — роль макета, как сейчас; свободная фигура — ближайшая
   ступень типографики ДС по кеглю. Зона внутри повтора получает номер повтора. Самая крупная
   зона вне повторов в верхней трети слайда — заголовок слайда. **Вместимость** — площадь рамки / площадь знака её
   кегля, как у плейсхолдеров (`parsing/capacity.py`).
3. **Страница ДС** получает раздел «Композиции»: миниатюра примера (превью уже рендерится
   для аудита, DS7), вид, зоны с вместимостью, повторы. Нет превью — раздел без миниатюр.
4. **Вид выбирает план, пример — счёт.** Меню ДС для плана (`design_menu`, #154)
   пополняется видами рецептов шаблона словами и с числом повторов («карточки: 3–4
   повтора»). План называет вид в `suggested_visual`. Соответствие значений
   `suggested_visual` видам рецептов задаёт одна таблица в `designsystem.recipes`, общая
   для всех шаблонов. `pick_recipe(slide_plan, recipes, previous)` берёт рецепты этого вида
   и отбрасывает не вмещающие: повторов меньше, чем пунктов; нет зоны под число; картинка
   без ассета. Из оставшихся берётся ближайший по числу повторов. При равенстве рецепты
   чередуются по номеру слайда, без одинаковых соседей. Нет рецепта названного вида — берётся
   любой вмещающий, нет и его — прежний путь через макет. Титул, перебивка и финал берут
   рецепт своего вида.
   Почему пример выбирает не модель: выбор между пятьюдесятью слайдами по описаниям модель
   делает хуже счёта. К тому же номер примера — это знание о файле, которого по ADR-003
   у генерации нет.
5. **Текст по зонам.** Композитор получает зоны рецепта (роль, вместимость, номер повтора)
   и пишет `SlideIR` с `recipe_id` и `zone_id` у блоков. Схема ответа — тот же `SlideIR`,
   лимиты зон — в промпте из реестра. Модель по-прежнему не видит .pptx, координат
   и цветов: только вид рецепта и зоны словами.
6. **Копирует writer, после композиции** (`rendering.recipe_slide`,
   `clone_recipe(prs, recipe, slide_ir, content)`). Для слайда с `recipe_id` — копия части
   слайда-примера со связями (картинки, диаграммы, макет), текст зон заменяется нашим
   с сохранением `rPr` первого прогона (гарнитура, кегль, цвет зоны), лишние повторы
   удаляются целиком с конца ряда, пустые зоны вне повторов удаляются (заголовок — никогда),
   картинка в области контента подменяется ассетом с обрезкой под рамку. Только после
   этого `_drop_sample_slides` удаляет исходные примеры. Слайд без `recipe_id` — как сейчас.
7. **Отчёт.** `run.json → design_system_usage`: `recipe` по каждому слайду (или `null`
   с причиной) и доля слайдов по рецепту; `run_metrics.py` — строка «слайдов по рецепту, %».
   Рецептов 0 — в заметках прогона: «рецептов нет — слайды собраны из макетов».
   Слайд по рецепту считается элементом ДС в `designsystem/usage.py` (`recipe:<вид>`).
   Иначе доля «слайдов с элементом ДС» упадёт ровно там, где колода стала выглядеть
   как шаблон.

### Пересмотр решения

Решение из `docs/agents/tasks-design-system.md:47–49`:

> Компонент поэтому — **параметрическое описание**, которое рисует наш рендерер,
> а не кусок XML, который копируется в слайд.

Рецепт копирует XML примера. Почему это с решением совместимо — и где его надо пересмотреть:

* **Что решение защищало — остаётся.** Оно стояло на двух опорах: LLM пишет только `SlideIR`
  (правило 4, ADR-001) и слайд — нативные объекты pptx (C3). Модель по-прежнему пишет только
  `SlideIR` — текст по `zone_id`; копирует и удаляет фигуры только writer. Скопированные
  фигуры — нативные фигуры PowerPoint с исходной геометрией, заливкой и порядком наложения,
  не картинка: C3 соблюдён.
* **ADR-003, «Условие пересмотра»** допускает это по духу. Там сказано: скопировать объект
  шаблона «как есть» можно **вне генерации**, прямой работой с файлом, не открывая генерации
  доступ к шаблону. Копирование и правда делается вне генерации: план и композитор видят
  только каталог рецептов в ДС (вид, зоны, вместимость), файл открывает writer. Но это не
  копирование «как есть»: рецепт меняет текст, удаляет повторы и пустые зоны. Подпадает ли
  такое под условие ADR — решает тимлид.
* **Правило 5 («цвет в IR — имя из темы») не нарушается.** В IR слайда по рецепту цвета нет
  вообще: цвет несёт фигура шаблона, которую никто не порождал. Литерал в файле — это цвет
  автора шаблона там, где он его сам поставил.
* **Правило 6 («кегль — только из шкалы шаблона») тоже цело — по той же причине.** В IR
  кегля нет. Стартовый кегль зоны — кегль автора в скопированной фигуре. Если текст не
  влезает, кегль уменьшается только по шкале шаблона (`domain.rules.next_size_down`).
* **Правило 2 тоже цело**: в коде ни RGB, ни имени макета, ни номера слайда — вид рецепта
  выводится из фигур.
* **Что пересматривается.** «Компонент рисует наш рендерер» перестаёт быть единственным путём:
  для слайдов по рецепту рендерер не рисует, а копирует. Параметрические компоненты остаются
  запасным путём — для слайдов без рецепта и шаблонов без примеров. Решает тимлид.

### Требования

**Требование: слайд по рецепту несёт оформление примера.**

- **WHEN** содержательному слайду подобран рецепт
- **THEN** на слайде все нетекстовые фигуры примера с исходной геометрией, заливкой и порядком
  наложения, цвета фигур не переписаны
- **AND** текст в зоне берёт гарнитуру, кегль и цвет из `rPr` первого прогона зоны примера;
  кегль уменьшается только по шкале шаблона (правило 6)

**Требование: рецепт подходит к содержанию.**

- **WHEN** у слайда три пункта, а у шаблона есть карточки на три и на четыре повтора
- **THEN** берётся рецепт на три
- **WHEN** у слайда нет ассета
- **THEN** рецепт с картинкой в области контента не выбирается
- **WHEN** два соседних содержательных слайда, и подходящих рецептов больше одного
- **THEN** они не берут один рецепт
- **WHEN** один и тот же сид
- **THEN** одна и та же колода

**Требование: структурные слайды тоже по шаблону.**

- **WHEN** у шаблона есть пример на макете вида титул / перебивка / финал
- **THEN** титул, перебивка и финал колоды берут рецепт своего вида

**Требование: лишнего из примера на слайде нет.**

- **WHEN** пунктов меньше, чем повторов в примере
- **THEN** лишние повторы удалены целиком (плашка вместе с текстом) с конца ряда
- **WHEN** зоне вне повтора не досталось текста
- **THEN** зона удалена; заголовок слайда не удаляется никогда
- **WHEN** у рецепта картинка в области контента
- **THEN** она заменена ассетом слайда с обрезкой под рамку; логотипы и декор вне области
  контента остаются

**Требование: текста шаблона в колоде нет — `template.sample_text_left`.**

- **WHEN** на слайде по рецепту осталась фигура с исходным текстом примера (нарушитель)
- **THEN** аудит даёт находку `template.sample_text_left`
- **WHEN** все зоны заменены нашим текстом или удалены (норма)
- **THEN** находки нет

**Требование: текст влезает в зону.**

- **WHEN** композиция пишет блок в зону
- **THEN** длина — в пределах вместимости зоны, `fit` сокращает до лимита, аудит переполнения
  на слайдах по рецепту зелёный

**Требование: рецепта нет — прежний путь.**

- **WHEN** под содержание слайда не нашлось рецепта
- **THEN** слайд собирается из макета, как сейчас; в `run.json` у слайда `recipe: null`
  и причина

**Требование: холодный шаблон работает как раньше.**

- **WHEN** у шаблона нет слайдов-примеров
- **THEN** рецептов 0, колода собирается прежним путём, в заметках прогона — «рецептов нет —
  слайды собраны из макетов»; `tests/e2e/test_cold_template.py` зелёный

**Требование: файл открывается без «восстановления».**

- **WHEN** колода записана со слайдами по рецепту
- **THEN** скопированные слайды несут все связи (картинки, макет, диаграммы), исходные примеры
  удалены после копирования, проверки `integrity.*` зелёные, LibreOffice рендерит без ошибок,
  python-pptx открывает файл

**Требование: дизайн-система показывает рецепты.**

- **WHEN** строится страница ДС шаблона с примерами
- **THEN** на ней раздел «Композиции»: миниатюра (если превью есть), вид, зоны с вместимостью,
  повторы; прежние разделы и их тесты (#142) не меняются

**Требование: ничего не зашито под шаблон и модель пишет только IR.**

- **WHEN** модели нужен рецепт
- **THEN** она видит вид и зоны словами и пишет текст по `zone_id`; копирует и удаляет фигуры
  только writer
- **WHEN** гейт C6 и `lint_no_template_constants.py`
- **THEN** чисто: ни RGB, ни имени макета, ни номера слайда в коде

## Проверка

Швы для тестов: `recipes()` на синтетическом манифесте и трёх VK; `pick_recipe()` на планах;
сквозной `write()` с IR по рецепту → открытие файла python-pptx и рендер LibreOffice — главный
шов, всё видимое пользователю проверяется там. Проверка аудита — на нарушителе и на норме
(правило 7). Холодный корпус (правило 10).

**Мерило**: «слайдов по рецепту, %» в `run.json` и `run_metrics.py`. Целевое — **≥ 60 %
содержательных слайдов** на трёх VK-шаблонах, без ухудшения прочих мерил (переполнение,
контраст, «слайдов с элементом ДС, %»); `design.unlike_the_template` должен улучшиться.
*Содержательный слайд* — любой, чей `intent` не титул, не перебивка и не финал.

## Что осталось незакрытым

* **Решения тимлида.** Нужны три: пересмотр «параметры, а не XML» вместе с ADR-003; четыре
  поля домена; владельцы `designsystem/**` и `rendering/recipe_slide.py`. До них код не пишется.
* **Путь Б** — рисовать плашки из компонентов ДС на пустом макете — отдельный change.
  Запасной путь здесь — нынешняя вёрстка по ДС.
* **Рецепты из примеров с диаграммой или таблицей** — подмена данных нативной диаграммы
  отдельная работа; такие слайды идут прежним путём.
* **Цитата** рецептом в v1 не выделяется: признака у фигур примера нет, рисуется по ДС.
* **Центрирование оставшихся повторов** (три карточки из четырёх) — только если рендер покажет
  перекос; v1 удаляет с конца ряда.
* **Описание `TemplateExample.slide_index`** («номер части slideN.xml») расходится с кодом
  (позиция в `sldIdLst`) — поправить вместе с полем `part_name`.
