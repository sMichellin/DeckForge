## Explore — ловятся ли s01, s10 прогона `a3a8f3a2319b`

Отчёт прогона прочитан со стенда (`GET /runs/a3a8f3a2319b/report`, только чтение):

| Слайд | Назначение | Находка до правки |
|---|---|---|
| s01 обложка | `ex014` (cover), макет `L09` (title), один заголовок, фактов нет | **нет** — только `design.ink_balance` (warning) |
| s10 финал | `ex014` (родственный cover), макет `L08`, один заголовок, факты f017, f018 | `integrity.content_lost` |

s01 не ловится ничем:

* `integrity.empty_slide` пропускает макет с нулевой вместимостью тела — «титул из одного
  заголовка по замыслу»; у `L09` она нулевая;
* `integrity.content_lost` судит только слайд, которому план дал факты, — обложке не давал.

Сверить тело с примером тоже нельзя: у `ex014` в манифесте записан один заголовок — рамка
таблицы автора в фигуры примера не попадает, и «пустое тело» по данным аудита выглядит
замыслом автора.

Решает правило продукта: после #287 (`the-closing-says-the-next-step`) обложке и финалу
строка помимо заголовка нужна **всегда** — «о чём колода и для кого», «что будет после»;
одним заголовком по замыслу бывает только раздел. Проверка отстала от этого правила.

## Propose

`integrity.empty_slide`: исключение «один заголовок по замыслу» — только разделу. Обложка
и финал (вид рецепта `cover`/`final`, без рецепта — вид макета `title`/`closing`) из одного
заголовка — находка `bookend_title_only` при любом макете.

Два прежних теста `test_audit_integrity.py` закрепляли старое правило («титул из одного
заголовка по замыслу») — переведены: норма — раздел; соседняя проверка теперь тоже называет
обложку из одного заголовка.
