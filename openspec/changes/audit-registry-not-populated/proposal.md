# audit-registry-not-populated

Ошибка в смерженном change (17). Capability: `audit-deterministic`, `pipeline-orchestration`.

Статус: proposed → applied

## Explore

Скрипт замера аудита (запрос из #26) на первом же прогоне показал 0 находок на 10 слайдах.
Причина оказалась не в замере:

```
после import runner:          0
после import проверок:       35
```

Проверки заводятся **побочным эффектом импорта** своего модуля (`@check(...)` в
`audit/deterministic/*.py` и `audit/semantic/*.py`). `AuditRunner` перебирает `REGISTRY`,
но сам их не импортирует. `cli.py` про это помнил и импортировал руками:

```python
from deckforge.audit import REGISTRY, deterministic  # noqa: F401  регистрация проверок
```

Узел `audit` графа — не помнил. То есть **в change (17) аудит колоды не выполнял ни одной
проверки**: `findings=0`, `passed=0`, `skipped=0`. Отчёт при этом получался неотличимым
от отчёта по чистой колоде — «нарушений не найдено». Ровно тот случай, против которого
у нас заведено правило «пропуск не выдаётся за успех», только на уровень выше: здесь
за успех выдавалось отсутствие самого аудита.

**Почему это не поймали тесты.** Мой сквозной тест утверждал `state["audit"] is not None` —
пустой отчёт под это подходит. Усиление утверждения не помогает: в общем прогоне pytest
реестр успевают наполнить импорты соседних тестовых модулей, и проверка зелена при любой
логике. Поймать можно только в чистом процессе.

## Propose

**Реестр наполняет сам прогон.** `audit/runner.py` импортирует модули проверок при импорте
себя. Помнить про побочный эффект обязан не каждый вызывающий, а тот, кто по реестру ходит:
вызывающих будет трое — CLI, граф и API потока C (change 23), — и забудет рано или поздно
любой.

**Гейт — в чистом процессе.** `test_runner_populates_the_registry_itself` запускает
подпроцесс, импортирует только `AuditRunner` и требует непустой реестр. Проверено, что без
правки тест падает (`0`), с правкой проходит.

Утверждение сквозного теста тоже усилено — `passed + findings > 0` вместо «отчёт есть», —
но в комментарии честно сказано, что этой конкретной ошибки он не ловит.

### Требования

**Требование: прогон аудита видит все объявленные проверки.** Импорта `AuditRunner`
SHALL быть достаточно, чтобы реестр был наполнен.

- **WHEN** процесс импортировал только `deckforge.audit.runner`
- **THEN** `len(REGISTRY) > 0`
- **AND** отчёт по колоде содержит либо находки, либо пройденные проверки

## Apply

`audit/runner.py` — импорт модулей проверок и абзац в docstring;
`tests/unit/test_audit_runner.py` — гейт в подпроцессе;
`tests/integration/test_pipeline_end_to_end.py` — усиленное утверждение.

## Что осталось незакрытым

1. **Цена ошибки в цифрах не измерена.** Насколько «аудит ничего не проверял» изменит
   отчёт на настоящей колоде — видно будет только на живом прогоне: у замерной колоды
   из макетов шаблона находок мало и без того.
2. **Тронут файл потока C** (`audit/runner.py`) — второй раз за день, оба раза аддитивно.
   Альтернатива — импортировать проверки в узле графа — чинит один вызов из трёх
   и оставляет ту же мину для change (23).
