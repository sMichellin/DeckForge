# languagetool-never-ran

Правка к changes (15) и (18). Capability: `audit-semantic`. Найдено при подъёме
LanguageTool на ml110 18.09.

Статус: proposed → applied

## Explore

Проверка `content.no_typos` («текст без опечаток», Приложение 1 ТЗ) **не работала
ни в одном окружении ни разу** — всегда уходила в пропущенные. Причин три, и каждая
по отдельности её выключала:

| Слой | Что было | Чей файл |
|---|---|---|
| `docker/compose.yaml` | `langtool_languageModel=/ngrams` при несмонтированном каталоге — сервис падал на старте: `LanguageModel directory not found` | тимлид |
| настройки | `DECKFORGE_LANGUAGETOOL_URL` объявлена в `config.py` и не читалась нигде; проверка брала адрес только из `server_url` в `audit_checks.yaml`, а там его нет | тимлид |
| проверка | `LanguageToolPublicAPI(lang, remote_server=url)` → `TypeError: got multiple values for keyword argument 'remote_server'`: класс сам задаёт адрес публичного сервиса. Фабрика глотала исключение и отдавала `None` | поток C |

Замер на живом сервере, текст «Выручка вырасла на 37 процетов»:

| Клиент | Результат |
|---|---|
| `LanguageToolPublicAPI(..., remote_server=url)` | `TypeError` при любом коде языка |
| `LanguageTool(..., remote_server=url)` | 2 опечатки: «вырасла», «процетов» |

**Почему тесты этого не ловили.** Все тесты проверки подменяют `checker_factory`
целиком — настоящий клиент в них не создавался ни разу. Проверка была «покрыта»
на подделке, которая сама по себе и была правильной.

Ещё одна деталь compose: в связке с Redis проверки выполняет **воркер**, а зависимость
от `languagetool` была объявлена только у `app`. Воркер про сервис не знал вовсе.

## Propose

1. **Проверка:** клиент для своего сервера — `LanguageTool`, а не `LanguageToolPublicAPI`.
   Одна строка в файле потока C; без неё остальные две правки бессмысленны.
2. **Адрес из окружения:** узел `audit` подаёт `server_url` из `DECKFORGE_LANGUAGETOOL_URL`
   через `run_params` (механизм #33). Адрес — свойство окружения, а не порог проверки;
   профиль, задав `server_url` явно, главнее.
3. **compose:** без n-грамм (для русского их нет вовсе), `DECKFORGE_LANGUAGETOOL_URL`
   указывает на имя сервиса в сети compose, воркер зависит от `languagetool`.

**Подавать адрес безопасно и без сервиса.** Проверено на живом сервере: при недоступном
адресе клиент падает сразу при создании (`LanguageToolError`, 0,0 с), фабрика это ловит,
проверка уходит в пропущенные. Посреди слайдов ничего не взрывается — а это важно:
прогонщик аудита ловит только `CheckUnavailable`, и исключение посреди проверки уронило
бы весь прогон.

### Требования

**Требование: проверка орфографии использует настроенный сервер.** Адрес
`DECKFORGE_LANGUAGETOOL_URL` SHALL доезжать до проверки `content.no_typos`.

- **WHEN** сервер доступен и в тексте опечатка
- **THEN** проверка даёт находку с предложенной заменой
- **WHEN** сервер недоступен
- **THEN** проверка попадает в `skipped_checks`, а аудит продолжается

## Verify

975 passed, 17 skipped; ruff, mypy strict, гейт C6. Четыре новых теста, и два из них
создают **настоящий** клиент библиотеки (подменён только сетевой класс), — ровно то,
чего не хватало, чтобы увидеть исходный дефект. Проверено на `language-tool-python`
2.9.5 — версии из `pyproject.toml`.

## Что осталось незакрытым

1. **Живая проверка в аудите — после деплоя.** Клиент на живом сервере проверен
   отдельно; что находки появляются в отчёте прогона, покажет прогон.
2. **Стенд на ml110 работает без compose:** API там в мостовой сети, и `localhost:8010`
   из `.env` указывает внутрь контейнера. Скрипт стенда переводит API в сеть хоста.
3. **MinIO в compose не использовался ничем** — в коде не было обращений к S3. Убран
   из compose вместе с настройками `DECKFORGE_S3_*` и зависимостью boto3.
