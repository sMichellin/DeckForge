# transport-error-not-validation

Правка к change (8). Capability: `inference`. Найдено сквозным прогоном на ml110 18.09.

Статус: proposed → applied

## Explore

Второй сквозной прогон упал за 16 секунд с сообщением:

```
InferenceError: DeckPlan: ответ не прошёл валидацию за 3 попыток:
```

Полчаса ушло на проверку схемы `DeckPlan`, промпта планировщика и совместимости
строгого режима. Настоящая причина лежала в конце того же сообщения, за двоеточием:
**404 от сервера инференса**, который в этот момент перезапускался. Модель не отвечала
вовсе — отвечать было нечему.

Так вышло потому, что цикл починки `generate_model` ловил `InferenceError` целиком:

```python
except (ValidationError, InferenceError) as exc:
    last_error = exc
    attempt_user = f"{user}\n\n{_repair_hint(exc)}"
```

Под этот тип попадают две разные вещи: «модель ответила, но ответ не разобрался»
и «провайдер отверг запрос». Первое чинится переспросом, второе — нет. В итоге
три попытки бились об один и тот же 404, а диагноз выдавался про схему.

## Propose

**Транспортный отказ — отдельный тип.** `InferenceTransportError` поднимается там же,
где раньше поднимался общий `InferenceError` на неретраебельный 4xx, и цикл починки
пробрасывает его как есть.

Граница проведена по вопросу «есть ли что переспрашивать»:

| Что случилось | Тип | Цикл починки |
|---|---|---|
| Ответ не разобрался как JSON | `InferenceError` | переспрашивает |
| Ответ не прошёл модель Pydantic | `ValidationError` | переспрашивает |
| Провайдер отверг запрос (404, 400) | `InferenceTransportError` | **пробрасывает** |
| Квота, занятость | `InferenceQuotaError` | пробрасывает (было и раньше) |

Повторы на уровне сети остаются у клиента (`tenacity`, `max_attempts`) — там им и место.

### Требования

**Требование: отказ провайдера не выдаётся за провал валидации.** Запрос, отвергнутый
провайдером, SHALL подниматься тем же типом, каким пришёл, без обёртки про схему.

- **WHEN** провайдер отвечает 404
- **THEN** вызывающий получает `InferenceTransportError` с кодом и сообщением
- **AND** модель не переспрашивается ни разу

## Verify

Два теста: отвергнутый запрос не повторяется (`calls == 1`), неразобравшийся ответ
по-прежнему чинится со второй попытки. 918 passed, 28 skipped; ruff, mypy strict чисты.

## Что осталось незакрытым

1. **Предполётной проверки эндпоинта нет.** Прогон по-прежнему начинается с парсинга
   шаблона и узнаёт о недоступной модели через минуту. Дешёвый `GET /v1/models`
   перед стартом графа сэкономил бы этот круг — но это узел графа, отдельная правка.
2. **`finish_reason: length` с пустым `content`** у размышляющих моделей клиент
   обрабатывает, но это не покрыто тестом на живом ответе — только на подделке.
