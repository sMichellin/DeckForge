# fix-grid-margins-body-kind

Правка change (4) `theme-extraction`. Capability: `design-system-extraction`.
Запрос потока B из change (14) (PR #12, «Что осталось незакрытым», п.1).

Статус: proposed → applied

## Explore

Запрос: «Поля сетки VK WorkSpace выведены неверно (нижнее поле 6,8 см): область
контента — 64 % высоты слайда, и диаграмма, поставленная в неё, сплющена».

Причина глубже, чем один неверный расчёт. У VK WorkSpace **все 15 макетов** — обложки,
разделители и декоративные заголовки; ни одного макета с телом контента (буллеты,
таблица, диаграмма, KPI). Разные макеты вертикально центрируют заголовок для красоты:

```
11_Заголовок      kind=title        y=424691   bottom=1592263   (типичный заголовок сверху)
7_Титульный слайд kind=image_full   y=2546255  bottom=4423145   (обложка, центр слайда)
```

`infer_margins` берёт `min(y)` и `max(bottom)` по **всем** макетам без разбора — это
даёт нижнее поле по самому «глубокому» заголовку (4423145 → поле 6,76 см), хотя это
геометрия одной декоративной обложки, а не граница, которую уважают остальные 14 макетов.

**Первая попытка чинить оказалась неверной.** Интуиция была: выброс, встретившийся
в одном-единственном макете, — не свойство сетки, а личная особенность этого макета
(та же логика, что уже применена к направляющим через `cluster_positions`). Применил
её к полям — и получил регресс: правое поле VK WorkSpace выросло с 1,13 см до 10,23 см.

Разбор показал, почему: макет `11_Заголовок` (кегль=title) — единственный на весь
шаблон с шириной плейсхолдера, доходящей до самого края (`right=11784013` при
слайде 12192000). Это ровно тот единичный случай, который делает поле честным
(1,13 см), но он тоже «выброс, встретившийся в одном макете» — фильтр по частоте
не может отличить «единственный удачный широкий макет» от «единственный неудачный
центрированный». Гео­метрия не несёт информации о том, декоративен макет или нет —
это знает только классификация (`LayoutKind`), которая для этого шаблона уже
посчитана: `_classify` в `template.py` выполняется **до** `infer_grid`.

Проверка по всем четырём шаблонам подтвердила: только у VK WorkSpace нет ни одного
макета с телом контента.

```
VK Tech       {'quote': 6, 'custom': 15, 'title': 16}                              — есть custom
VK WorkSpace  {'title': 8, 'section': 4, 'image_full': 3}                          — тела нет вовсе
VK Education  {'quote': 8, 'title': 7, 'bullets': 4, 'two_column': 7, 'custom': 4} — есть bullets
ЛЦТ2026       {'section': 3, 'custom': 5, 'kpi': 6, 'two_column': 4, ...}          — есть kpi
```

## Propose

Не подрезать выбросы статистически, а спросить, есть ли вообще макет, чья геометрия
годится в основание сетки: `LayoutKind.{BULLETS, TWO_COLUMN, CHART, TABLE, KPI, CUSTOM}`.

* Если такой макет есть хотя бы один — алгоритм не меняется вовсе: `min`/`max`
  по-прежнему считается по всем нефулбличным плейсхолдерам, как раньше. Это ровно то
  поведение, что уже работает на VK Tech, VK Education и ЛЦТ2026.
* Если такого макета нет — единственный источник геометрии декоративный, а декоративные
  макеты по двум осям «врут» в противоположные стороны (проверено выше: подрезка одной
  оси чинит вертикаль и ломает горизонталь). Возвращаются обычные поля презентации —
  7 % по ширине, 10 % по высоте, — не подогнанные под конкретный шаблон.

## Apply

`parsing/grid.py`: `_BODY_KINDS`, `_FALLBACK_MARGIN_SHARE_{X,Y}`, ранний выход
в `infer_margins`. `layouts` передаётся в `infer_margins` уже после классификации
(`_classify` в `template.py` вызывается раньше `infer_grid`) — новых зависимостей
между модулями не появилось.

## Verify

Диф с `origin/main` — чистое добавление: путь для шаблонов с телом контента байт
в байт совпадает с тем, что было. Проверено сверкой:

| Шаблон | До | После |
|---|---|---|
| VK Tech | не менялся | content 94%×84% |
| VK Education | не менялся | content 90%×88% |
| ЛЦТ2026 | не менялся | content 98%×92% |
| **VK WorkSpace** | **content 66%×55%** (правое поле 10,2 см — от неудачной первой попытки; в `main` до неё было 58% по высоте) | **content 86%×80%** |

515 тестов (было 513 после мержа PR #12, добавлены два: фолбэк срабатывает при
отсутствии body-kind, и не срабатывает при наличии хотя бы одного), ruff и mypy
чистые, гейты C1/C2 и C6 проходят.

## Что осталось незакрытым

Запасные 7 %/10 % — универсальная константа, не подогнанная под шаблон, но и не
выведенная из данных: для шаблона без единого макета с телом контента лучшего источника
геометрии просто нет. Если такие шаблоны на защите встретятся часто, стоит завести это
отдельным полем провенанса в `Grid` (по аналогии с `guides_source`), чтобы аудит и UI
могли явно показать: поля здесь не выведены, а угаданы.
