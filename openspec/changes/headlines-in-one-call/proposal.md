# headlines-in-one-call

Правка change (10) `deck-planning`. Следствие A4.

## Explore

Прогон `e6e1f2283ca8` после #84: заголовки стали помещаться — восемь из девяти
переписанных встали в рамку против четырёх из десяти до этого. Но стадия `plan`
выросла с 42 с до 171 с, а прогон целиком — до 392 с при бюджете C5 в 300.

Причина арифметическая. Переписывание идёт по одному заголовку на вызов: девять
не уместившихся плюс шесть вторых заходов — пятнадцать запросов. Сервер локальной
модели однослотовый, параллелить нечего, каждый вызов стоит 8–9 с.

## Propose

Один вызов на всю колоду вместо одного на заголовок: модель получает список заголовков
с их пределами и возвращает список переписанных. Второй заход — тоже один вызов,
для тех, кто не уместился.

Пятнадцать запросов превращаются в два. Качество при этом не размывается: у каждого
заголовка в запросе стоит свой предел и свой промах, а факты слайда идут рядом с ним.

Версия промпта новая — `headline_writer@1.1.0`: контракт ответа изменился
(объект → список), а версии промптов для того и существуют (C9). `1.0.0` остаётся
на месте: он объявлен для авто-фикса `regenerate_headline`, который переписывает
ровно один заголовок по находке аудита.

## Verify

Тесты: оба захода укладываются в два запроса; в запросе второго захода стоит промах
по каждому не уместившемуся заголовку; ответ, в котором модель вернула не все слайды,
не роняет прогон — недостающие остаются с прежним заголовком.
