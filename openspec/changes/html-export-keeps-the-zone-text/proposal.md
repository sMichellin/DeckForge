## Explore

Прогон `5cf2705fc173` (24.09, `d4e0d60`, таск RG2) впервые дошёл до стадии `export` —
прежде падал раньше, в `render`, — и упал там:

```
AttributeError: 'NoneType' object has no attribute 'bbox'
```

`export/html.py:216`:

```python
box = block.bbox
if box is None and isinstance(block, TextBlock | BulletsBlock):
    placeholder = layout.placeholder(block.placeholder_idx)
    box = placeholder.bbox          # placeholder может быть None
```

У блока в зоне рецепта нет ни координат, ни `placeholder_idx`: рамку ему дал автор
шаблона, и в IR её нет вовсе. `layout.placeholder(None)` возвращает `None`. В прогоне
таких блоков четырнадцать на девяти слайдах из десяти:

```
s01 [b01]                s06 [b01]
s02 [b01, b02, b02-1]    s07 [b01]
s03 [b01, b02, b02-1]    s08 [b01, b02, b02-1, b02-2, b02-3]
s04 [b01]                s09 [b01]
s05 [b0]
```

Дефект не новый: он лежит здесь с `compose-by-the-recipe`. Строкой ниже тот же файл
берёт `fit_report` через `in`, то есть проверку там сделали, а здесь нет.

Цена высокая не сама по себе, а по месту: **колода к этому моменту уже записана**.
`deck.pptx` на 10 слайдов и `deck.pdf` лежали в `out/`, а прогон всё равно `failed` —
и в UI это «скачать» с ошибкой.

**Чего сделать нельзя.** Нарисовать блок там же, где его рисует PowerPoint, не получится:
у `Zone` (`designsystem/models.py:382`) есть `capacity_chars` и `size_pt`, но **геометрии
нет**. Она известна разбору примеров, а каталог её не сохраняет. Добавить её — правка
`designsystem/**`, это поток A, и это отдельный change.

**Чего делать не стоит.** Вернуть `""` для блока без рамки — дёшево, прогон зеленеет,
но html показывает девять слайдов из десяти пустыми. Это не «html готов», это html,
который врёт про колоду. Выбрано третье.

## Propose

1. **Не падать.** `placeholder.bbox if placeholder is not None else None`. Это касается
   не только зон: блок с номером плейсхолдера, которого нет в макете, падал так же.
2. **Слайд по рецепту html верстает потоком.** Блоки в зонах собираются в полосу
   `.zones`, поставленную по области контента шаблона, и идут в ней в порядке зон:
   заголовок, потом тело. Текст и порядок чтения целы, точное место — нет, и это
   названо комментарием в CSS.
3. **Рамка блоку в зоне не выписывается** (`frame()` вместо `place()`): инлайновый стиль
   сильнее правила класса, и `width` из `style` перебил бы `width: auto` — блок вышел бы
   из потока полосы.
4. **Кегль без отчёта о вписывании берётся из типошкалы.** У блока в зоне записи в
   `fit_report` нет и быть не может — вписывание его не мерило (`SlideIR.by_recipe`,
   RG3). Прежний `size or 0` дал бы `font-size: 0`, то есть невидимый текст вместо
   видимого. То же решение, что RG5 принимает в писателе.

Правка ограничена `export/html.py`. Каталог, домен и граф не тронуты.

## Что осталось незакрытым

* **Место блока в html не то, что в pptx.** Пока у `Zone` нет геометрии, html показывает
  слайд по рецепту как текст в области контента, а не как вёрстку автора шаблона.
  Настоящее решение — геометрия зоны в каталоге (`designsystem/recipes.py`, поток A):
  разбор примеров рамку фигуры знает, каталог её выбрасывает. Запрос потоку A.
* **Спеки у `export-formats` нет.** Capability объявлена в `openspec/project.md`, файла
  в `openspec/specs/` не заведено, поэтому у этого change'а `skip_specs`. Завести —
  отдельная работа.
* ~~Прогон на ml110 после правки~~ — **сделан**: `3dd589541036` на `cbc1d37`, те же
  параметры. `state: done`, `error: null`, 248,8 с. В `out/` — `deck.pptx`, `deck.pdf`,
  `deck.html` (10 КБ, девять полос `.zones`, десять секций слайдов, нулевых кеглей нет,
  текст зон на месте). Первый зелёный сквозной прогон.
* **Оговорки в отчёте нет.** «Html собран потоком, а не по рамкам шаблона» стоило бы
  видеть в `degradations` прогона, но `export_html` их не возвращает, а узел `export`
  их не собирает (`pipeline/nodes/export.py` — файл тимлида). Запрос тимлиду вместе
  с RG17.
