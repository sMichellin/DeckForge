# compose-by-the-design-system

Capability: `slide-composition`. Основание:
[docs/agents/tasks-design-system-in-generation.md](../../../docs/agents/tasks-design-system-in-generation.md),
задача DG3; требование R23 брифа прогона `design-system-page` — «агент просто кладёт
текст на слайд».

Статус: accepted (тимлид, 22.09). Исполнители — поток A (`composition/**`, `prompts/**`) и поток B
(`layout/**`, `rendering/**`), по файлам не пересекаются. Зависит от
`design-system-in-the-pipeline` (DG2) и `ir-callout-and-quote` (DG4).

## Explore

Это тот самый шаг, ради которого затевалась вся дизайн-система: заказчица хотела,
чтобы слайды верстались по ней, а не «текст на слайд». Сейчас композиция и вёрстка
решают сами то, на что ДС уже ответила числом по шаблону:

| Решение | Где принимается сейчас | Что об этом знает ДС |
|---|---|---|
| Каким цветом блок | слот темы по месту (`writer`), акценты по порядку | `palette_roles`: роль цвета по доле площади примеров |
| Каким кеглем число | своё правило KPI (регрессия B13, #139) | `number_sizes`: крупное, среднее, мелкое из KPI-примера шаблона |
| Пропорции и зазор компонента | `manifest.components` напрямую (DS4) | `components`: доли ширины, высоты и зазора |
| Отступ между блоками | шаг сетки манифеста | `grid.spacing`: базовый шаг и его кратности |
| Маркер и отступ списка | `manifest.bullet_levels` | `bullets` плюс три стиля списка из `synthesized` |

Разница не косметическая: ДС меряет **по слайдам-примерам шаблона**, то есть по тому,
как автор шаблона сам оформлял слайды, а не по тому, что объявлено в мастере.

## Propose

1. **Композиция получает ДС из состояния** (после DG2) и передаёт в решатель вёрстки.
   Модель по-прежнему не видит координат (PPTBench, tasks-21-09): в промпт уходят роли
   и виды компонентов, а не EMU.
2. **Роль цвета блока — из `palette_roles`.** Акцент берётся тот, который шаблон
   действительно использует как акцент, а не `accent1` по порядку. Цвет в IR остаётся
   именем слота (правило 5).
3. **Кегль числа — из `number_sizes`.** Правило вёрстки KPI перестаёт быть своим:
   крупное значение — `large_pt`, подпись — `small_pt`, обе ступени из шкалы шаблона
   (правило 6).
4. **Отступы и пропорции — из `grid.spacing` и `components`** вместо прямого чтения
   манифеста: у ДС они уже сведены к шагу и долям, и это единственное место, где
   решается, чему кратен отступ.
5. **Три стиля списка** (маркированный, нумерованный, иконочный) — композиция выбирает
   стиль, вёрстка рисует его параметрами ДС.

### Требования

**Требование: акцент выбирается по шаблону, а не по номеру слота.**

- **WHEN** у шаблона роль `accent` по площади — не `accent1`
- **THEN** блок с акцентом получает именно её
- **WHEN** примеров в шаблоне нет и роли не измерены
- **THEN** поведение прежнее, и это отмечено в заметках прогона

**Требование: кегль числа берётся из ДС.**

- **WHEN** ДС измерила `number_sizes.large_pt`
- **THEN** значение показателя набрано им, а подпись — `small_pt`
- **WHEN** не измерила
- **THEN** работает нынешняя ступень шкалы

## Проверка

Три прогона с разными сидами на трёх шаблонах, до и после, плюс пересборка по чекпойнту
без модели для правок вёрстки (так делались #100 и #139):

* `scripts/run_metrics.py`: визуализаций, заголовков подрезано, ошибок аудита, время;
* C9: доля слайдов с пустой зоной ≥ 40 % ширины;
* ни одно число не хуже нынешнего; целевое — рост доли слайдов, где цвет и кегль
  совпали с профилем шаблона (DS7).

Тесты на нарушителе и на норме, холодный шаблон (правило 10), гейт C6.

## Что заведомо останется незакрытым

Оценка «похоже на шаблон» глазами: метрики ловят пустоту и контраст, но не вкус.
Смотреть четыре собранные колоды придётся человеку — как и четыре страницы из #142.
