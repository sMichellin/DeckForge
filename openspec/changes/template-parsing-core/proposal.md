# template-parsing-core

Change (3) из ARCHITECTURE.md §14. Capability: `template-parsing`.

Статус: proposed → applied

## Explore

Манифест — вход для всего, что выше по пайплайну (ADR-003), поэтому от его полноты
зависит, заработает ли композиция вообще. Разбор четырёх настоящих шаблонов (три от
организаторов плюс шаблон питча ЛЦТ) показал, что расчёт на «типовой» .pptx неверен:

| Наблюдение | Шаблоны | Что это ломает |
|---|---|---|
| Мастеров больше одного, у каждого своя тема | 3 из 4 | «читаем `ppt/theme/theme1.xml`» даёт не ту палитру |
| Мастер пуст, вся геометрия в макетах | VK Tech | наследование «макет берёт у мастера» само по себе не покрывает |
| В макетах только титул, контентных плейсхолдеров нет | VK WorkSpace | вместимость честно нулевая, это не ошибка парсера |
| Макетов 15–39, имена вида «2_Титульный слайд», «1_Контент» | все | по имени вид макета не определить (C6) |

## Propose

Читать пакет как OPC-архив (zip + lxml) и собирать `TemplateManifest` из того, что
в нём есть, ничего не достраивая по умолчанию:

* `parsing/package.py` — доступ к частям и связям; порядок мастеров берётся из
  `presentation.xml`, а не из имён файлов;
* `parsing/ooxml/layouts.py` — плейсхолдеры с каскадом `slideMaster → slideLayout`;
* `parsing/ooxml/decor.py` — логотип, колонтитул, статичные фигуры (вход для
  `template.decor_moved`);
* `parsing/capacity.py` — вместимость из площади и кегля;
* `parsing/layout_kind.py` — вид макета по геометрии, с записью уверенности;
* `parsing/template.py` — сборка и кэш по SHA-256.

**Отклонение от §4.1.** Архитектура предписывала брать плейсхолдеры через python-pptx.
Здесь используется прямой разбор — обоснование в [ADR-008](../../docs/adr/008-opc-direct-parsing.md).

**Уточнение сигнатур заглушек.** `compute_capacity` и `classify_heuristic` в каркасе
принимали `LayoutSpec`/`TemplateManifest`, которых на момент вызова ещё не существует
(вместимость нужна, чтобы собрать `LayoutSpec`). Обе принимают плейсхолдеры и шкалу.
`extract_guides` читает `viewProps.xml`, а не мастер: направляющие лежат там.

## Apply

Реализовано полностью. Добавлен `NotATemplateError`: пользователь, загрузивший не тот
файл, должен увидеть внятное сообщение, а не `zipfile.BadZipFile`.

Попутно закрыта дыра в гейте C6: регулярное выражение `\d{5,}` пропускало литералы
с разделителями разрядов (`1_200_000`), то есть ровно тот стиль записи, которым удобно
зашить размер в EMU. Ужесточено до `\d[\d_]{4,}`; заодно починен путь в allowlist,
из-за которого `domain/units.py` не распознавался как разрешённый модуль.

## Verify

* `tests/unit/test_ooxml_layouts.py` — каскад, пустой мастер, отбрасывание плейсхолдеров
  без геометрии, дубли idx, титул без атрибута `idx`;
* `tests/unit/test_layout_kind_and_capacity.py` — вид макета по геометрии, вместимость;
* `tests/integration/test_template_parsing.py` — полный разбор синтетического пакета, кэш,
  инвалидация кэша по версии парсера, понятные ошибки;
* `tests/golden/test_manifest_snapshot.py` — снапшот манифеста;
* `tests/integration/test_real_templates.py` — четыре настоящих шаблона (файлы в git
  не хранятся, тест пропускается без них).

Прогон на настоящих шаблонах: 259 passed. Гейты C1/C2 и C6 зелёные, mypy strict чист.
