# matrix-tiles

Правка changes (21) `smartart-icons` и (10) `deck-planning`. Задания B6 и A5
из `docs/agents/tasks-21-09.md`.

## Explore

Визуализаций на колоду — медиана 1 на шести прогонах подряд. Подход assertion–evidence
(Penn State; исследование понимания: аудитория колоды «утверждение + визуальное
доказательство» понимает и запоминает лучше, чем аудитория «тема + буллеты») требует
доказательства на каждом содержательном слайде. У нас заголовки-утверждения есть,
доказательства почти нет.

Материал при этом полон перечислений, которые просятся в схему: «инференс, шаблоны,
контент, CLI», «специалисты по данным, инженер ML». Но нарисовать их нечем: из видов
схем поддержаны процесс, шкала времени и цикл — все три со стрелками или осью, то есть
с порядком. Перечисление, нарисованное процессом, врёт о последовательности, поэтому
план честно отдаёт его буллетами. `SmartArtPattern.MATRIX` объявлен в домене, но
`layout/diagram.py` его не рисует.

## Propose

1. **B6 — плитки.** `matrix` раскладывается сеткой: до трёх в ряд, четыре квадратом,
   пять-шесть по три; без стрелок; плитка не выше 0,6 своей ширины; сетка по середине
   рамки, неполный нижний ряд по центру. Через `diagram_geometry` проходят и вписывание,
   и pptx, и html — отдельно их трогать не нужно.
2. **A5 — заказ.** Планировщик получает признак: три–шесть однородных коротких пунктов
   одного рода → `smartart:matrix`. И правило: тезисы — последнее средство; если есть
   из чего собрать схему, заказывается схема. Композитор узнаёт, чем `matrix` отличается
   от `process`.

## Verify

Тесты: четыре плитки — сетка 2×2 без стрелок; пять — нижний ряд по центру; сетка по
середине рамки; общий тест «всё внутри рамки, ничего не перекрывается» подхватывает
`matrix` сам. Эффект заказа — тремя прогонами через `run_metrics.py`: визуализаций
медиана 1 → больше.
