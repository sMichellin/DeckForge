# the-by-example-path-is-wired

План Б, стык шагов 3 и 5б (ADR-009). Тимлид, `pipeline/**`. Capability `pipeline-orchestration`.
Запросы: поток A — #261 (запросы 1–3), поток B — #259 (запросы 1–2).

## Explore

После #261 и #259 механизм пути `by_example` есть в каждом слое, но граф его не доносит:

* узел `compose` не передаёт композитору назначение слайда (`state["assignments"]`) и шрифты —
  композитор идёт прежним путём даже на `by_example`;
* заголовок переписывается под полосу **макета**, а на новом пути встаёт в **место примера**
  со своим пределом — заголовок переписан под одну рамку и просится в другую;
* узлы `fit`, `render`, `export` не знают пути: вписывание не меряет схему слайда без примера,
  а писатель с `by_example=True` без замера её не пишет (так задумано в 5б); узел `fit`
  сплющивает схему и снимает текст раньше писателя (`_smartart_to_bullets`,
  `_bullets_drop_tail`, `_text_last_resort`);
* старт прогона на `by_example` отказывает (`ensure_composition_path`) — причина отказа
  («`compose` не пишет под места») исчерпана #261.

## Propose

* `compose`: `SlideComposer(..., fonts=deps.fonts)` и `assignment=` из назначений состояния.
  Полоса заголовка слайда с назначенным примером — место заголовка его паспорта
  (`_bands_of_assigned_places`): мерило — `passport.fit_measure`, предел — ёмкость места.
  Место под число полосой не считается (как полоса макета короче двух слов).
* `fit`: путь из `state["composition_path"]` в `fit_slide`; для слайда без примера на пути
  `by_example` (`layout.diagram.goes_by_design`) три функции сплющивания и снятия не зовутся.
* `render` и `export`: тот же флаг в `export_pptx` и `export_html`. `export/pptx.py` (файл B) —
  две строки проброса параметра, без логики.
* Отказ старта снят вместе с функцией; тесты change 0 на отказ удалены, требование
  «новый путь без своего узла не подменяется старым» закрыто этим change.

На пути `legacy` назначений нет и флаг `False` — поведение прежнее, это проверяется тестом.

## Verify

`tests/unit/test_the_by_example_path_is_wired.py` — норма и нарушитель на каждый шов:

* `compose`: назначение и шрифты доходят до композитора (норма); на `legacy` назначения нет (норма);
* полоса заголовка: у слайда с примером — предел места заголовка паспорта (норма, фикстура VK Tech
  28.09 после узла `assign`); слайд без примера полосы места не получает (нарушитель);
* `fit`: длинная схема слайда без примера на `by_example` остаётся схемой с замером (норма),
  на `legacy` — список (нарушитель); иерархия получает замер только на `by_example`;
* вписывание + `export_pptx` на `by_example` пишут схему без отказа писателя (норма).

Строки приёмки 4, 5, 6, 9, 10 меряет первый живой прогон `by_example` на стенде plan-b —
этот change делает его возможным и сам чисел приёмки не двигает.

## Что осталось незакрытым

* Цикл сокращения `shorten`/`split` в узле `fit` на слайде без примера остаётся: текст режется
  словами, а не снимается (строка 6). Делить слайд до записи по-прежнему некому.
* Потери полями, а не текстом заметок (запрос 4 A) — отдельное решение по `domain/**`.
* Активная версия `slide_composer` в `prompts/registry.yaml` — вместе с приёмкой.
