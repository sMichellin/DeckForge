# closing-slide-has-a-recipe

Правка change `compose-by-the-recipe` (таск 05b), capability `slide-composition`.
Парная к `recipe-is-not-the-models-word`: та убирает падение, эта — причину, по которой
последний слайд выпадает из дизайн-системы.

Статус: implemented, ждёт ревью (24.09). Ветка `feat/closing-slide-has-a-recipe`, таск RG8.
Файлы: `composition/recipe_picker.py`, `composition/composer.py` (одна строка — `notes`), поток A.

## Explore

Во всех пяти прогонах 24.09 без рецепта остался ровно один слайд — последний, `s10`.
Не случайность: у него `intent = CLOSING`, а `pick_recipe`
(`composition/recipe_picker.py`) для структурных мест колоды **не имеет отката**:

```python
wanted = INTENT_KINDS.get(slide.intent) or kind_for_visual(slide.suggested_visual)
if slide.intent in INTENT_KINDS:              # TITLE / SECTION / CLOSING
    same = [recipe for recipe in recipes if recipe.kind is wanted]
    return _nearest(same, slide, previous, has_asset=has_asset)   # нет вида → None
```

Содержательный слайд, не найдя рецепт названного вида, берёт любой вмещающий
(`_nearest(named, …) or _nearest(fitting, …)`). Структурный не берёт ничего.

Виды в каталоге шаблона `VK_WorkSpace_Клиентская_конференция_Шаблон_03.pptx`
(29 рецептов, из чекпойнта `b5babbdac83f`):

| Вид | Рецептов |
|---|---|
| `text` | 17 |
| `cards` | 6 |
| `text_with_picture` | 4 |
| `cover` | 1 |
| `section` | 1 |
| **`final`** | **0** |

Вида `final` у шаблона нет — и закрывающий слайд гарантированно получает `None`.
Дальше выдумка модели проходила в `DeckIR` (см. `recipe-is-not-the-models-word`).
После той правки падения не будет, но `s10` всё равно соберётся на пустом макете:
фон, плашки и декор шаблона на него не попадут — то самое «от 87 до 96 % оформления
живёт вне плейсхолдеров», из-за чего рецепты и вводились.

То есть «агент не работает по дизайн-системе» на e2e имеет два слагаемых: утечка
контракта (change 1) и **дырка в отображении «место в колоде → вид композиции»**:
каталог классифицирует примеры по пяти видам, а `INTENT_KINDS` требует вид, которого
у шаблона может не быть вовсе. Проверить это на трёх шаблонах кейса до правки —
часть работы: `final` может отсутствовать у всех трёх.

## Propose

1. **Структурный слайд получает откат.** Порядок: рецепт своего вида → рецепт
   родственного вида → любой вмещающий не-структурный → `None`. Родство объявляется
   таблицей, не эвристикой:

   | Место | Свой вид | Родственный |
   |---|---|---|
   | `TITLE` | `cover` | `section` |
   | `SECTION` | `section` | `cover` |
   | `CLOSING` | `final` | `section`, `cover` |

   Закрывающий слайд по виду ближе к разделителю, чем к обычному текстовому: одна
   крупная фраза, без ряда карточек. Если и родственного нет — вмещающий содержательный
   рецепт: слайд в оформлении шаблона лучше слайда на пустом макете.
2. **Откат называется.** `SlideComposer.notes`: «s10: рецепта вида `final` в шаблоне нет,
   взят `ex002` (`section`)». Отчёт прогона (`design_system_usage`) это уже показывает
   по слайдам — станет видно без чтения логов.
3. **Замер перед выбором варианта.** По трём шаблонам кейса выписать, какие виды
   каталог находит и сколько примеров у каждого. Если `final` не находится ни у одного,
   проверить отдельно: это отсутствие таких слайдов в шаблонах или недобор в
   `designsystem/recipes.kind_for_*`. Второе — правка каталога, а не подборщика,
   и тогда change ветвится. Решение по итогам замера — за владельцем.

Ничего в коде не зашивается под конкретный шаблон: и виды, и примеры приходят из
каталога (`scripts/lint_no_template_constants.py`).

## Замер (24.09, до кода)

Каталог `derive(manifest).recipes` по шаблонам кейса и холодным из `tests/fixtures/templates`:

| Шаблон | Примеров | Рецептов | Виды |
|---|---|---|---|
| VK Tech | 54 | 54 | `text` 30, `text_with_picture` 14, `cards` 9, `metrics` 1 |
| VK WorkSpace | 29 | 29 | `text` 17, `cards` 6, `text_with_picture` 4, `cover` 1, `section` 1 |
| VK Education | 55 | 45 | `text` 20, `cover` 11, `text_with_picture` 11, `cards` 3 |
| холодные (6 шт.) | 1–9 | 0–1 | у `Grey_Elegant` один `text`, у остальных пусто |

**`final` нет ни у одного.** При этом закрывающие слайды в шаблонах **есть**: «Спасибо
за внимание» — VK Tech `ex004`–`ex006`, VK WorkSpace `ex029`, VK Education `ex052`.
Каталог записывает их в `text`: вид `final` он даёт только примеру на макете, который
классификатор назвал `CLOSING` (`recipes.STRUCTURAL_KINDS`), а эти макеты размечены
`custom`, `quote` и `section` (`parsing/layout_kind.py`: `CLOSING` — только «заголовок
без тела и подзаголовка»). То есть это **недобор каталога**, а не отсутствие слайдов —
по правилу задания правка каталога уходит отдельным change'ем, решение за тимлидом.
Откат в подборщике нужен при любом решении: у VK Tech нет и `cover` с `section`.

## Что сделано

`pick_recipe` для структурного места: свой вид → родственный по таблице `RELATED_KINDS`
→ вмещающий содержательный → `None`. Откат пишется в `notes` («слайд s10: рецепта вида
«final» в шаблоне нет, взят ex002 («section»)»), композитор передаёт свой отчёт.
Содержательные слайды — без изменений.

Уточнение дельты: `None` — не только при пустом каталоге, но и когда ни один рецепт не
вмещает слайд (все требуют картинку, а ассета нет): это то же правило вмещения, что
у содержательных слайдов, и тот же исход. Добавлены сценарий на это и требование
«родство задано таблицей» с тремя сценариями.

Структурные места колоды с рецептом, до → после:

| Шаблон | `title` | `section` | `closing` |
|---|---|---|---|
| VK Tech | — → `text` | — → `text` | — → `text` |
| VK WorkSpace | `cover` → `cover` | `section` → `section` | — → **`section`** |
| VK Education | `cover` → `cover` | — → `cover` | — → **`cover`** |

На шаблоне прогона `b5babbdac83f` (VK WorkSpace) — 10 из 10 по каталогу вместо 9.

## Что осталось незакрытым

* **Каталог не узнаёт закрывающие слайды** (замер выше) — предложение в capability
  `design-system-extraction`: признак `final` не только по виду макета. Кандидаты
  без констант шаблона — последний структурный пример шаблона, макет без тела после
  содержательных. **Решение тимлида**; до него VK Tech закрывается вмещающим `text`,
  а не «Спасибо» шаблона.
* **Живой прогон** на ml110: у `s10` в отчёте `exNNN` из каталога, в `notes` — причина
  отката; три шаблона и холодный (RG20).
