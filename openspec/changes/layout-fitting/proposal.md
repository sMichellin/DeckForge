# layout-fitting

Change (12) из ARCHITECTURE.md §14. Capability: `layout-fitting`. Поток B.

Статус: proposed → applied

## Explore

Задача — ловить переполнение текста **до** записи файла настоящими метриками гарнитуры,
а не оценкой по средней ширине знака (`parsing/capacity.py`, `_AVG_CHAR_WIDTH_RATIO = 0.52`).

### 1. Шрифт из темы — не тот шрифт, которым набран текст

У всех трёх шаблонов кейса тема объявляет `Arial`, а текст в макетах и слайдах набран
**Play** — явным `<a:latin typeface>` поверх темы:

| Шаблон | `theme.fonts` | Чаще всего в `slideLayouts` / `slides` |
|---|---|---|
| VK Tech | Arial / Arial | Play (273 / 2238), Calibri |
| VK WorkSpace | Arial / Arial | Play (45 / 1080), Arial |
| VK Education | Arial / Arial | Play (153 / 945), Arial |

`TypographyStep.font_ref` указывает на тему, поэтому из манифеста получается `Arial`.
Настоящей гарнитуры плейсхолдера в манифесте нет — это поле контракта, см. «Запросы тимлиду».

### 2. Шрифт шаблона не прочитать даже там, где он вшит

Play лежит в пакете (`ppt/fonts/Play-regular.fntdata`), но это **EOT со сжатием
MicroType Express** (флаг `TTEMBED_TTCOMPRESSED` в заголовке): fontTools его не открывает,
а распаковщика MTX на Python нет. К тому же слой `layout` файла шаблона не видит (ADR-003).

Вывод: в образе воркера (Liberation, DejaVu, Noto) шрифта шаблона **не будет почти никогда**.
Запасная стратегия — не крайний случай, а основной режим работы.

### 3. Насколько гарнитуры расходятся по ширине

Ширина одной и той же строки (101 знак, кириллица с латиницей) в долях кегля:

| Гарнитура | Ширина, em | к Play |
|---|---|---|
| Play (шаблон, OFL) | 48,8 | — |
| Arial | 49,0 | +0,4 % |
| Tahoma | 48,9 | +0,2 % |
| Segoe UI | 48,4 | −0,9 % |
| Calibri | 44,6 | −8,6 % |
| Verdana | 55,6 | +13,8 % |
| DejaVu Sans | 56,0 | +14,6 % |
| старая оценка 0,52 | 52,5 | +7,5 % |

Оценка по средней ширине ошибается в **обе** стороны: для Calibri завышает на 18 %,
для DejaVu занижает на 6 %. Поэтому для узких шрифтов она зря уменьшает кегль,
а для широких пропускает переполнение.

### 4. Высота строки — правило формата, а не шрифта

Рендер LibreOffice (текстбокс из pptx, 20 pt, 8 строк) даёт шаг строки **ровно 1,2 кегля**
для Arial, DejaVu Sans, Play, Calibri, Verdana, Segoe UI и даже Cambria Math и Gabriola,
у которых `winAscent + winDescent` сильно больше 1,2 em. То же правило «одинарный
интерлиньяж = 1,2 кегля» действует в PowerPoint. Метрики `hhea`/`OS/2` для высоты
строки не используются.

## Propose

### `layout/fonts.py` — где взять файл шрифта

`FontLibrary` индексирует каталоги шрифтов (`name` и `OS/2`, лениво, `.ttf/.otf/.ttc`):

* каталоги: `DECKFORGE_FONT_DIRS` (через `os.pathsep`) → `assets/fonts` → системные;
* поиск по семейству (name ID 16, затем 1) без учёта регистра, с подбором начертания;
* **нет шрифта → пессимистичная замена**: из пропорциональных гарнитур нормальной ширины
  (`usWidthClass = 5`, без моноширинных и курсивов), покрывающих кириллицу и латиницу,
  берётся **верхний квартиль по ширине** на пробной строке из алфавитов;
* замена берётся из **первого каталога**, где есть подходящие гарнитуры: `DECKFORGE_FONT_DIRS`
  и `assets/fonts` задают её воспроизводимо, какие бы шрифты ни стояли на машине;
* выбор детерминирован (равенство — по пути файла) и кэшируется.

Почему пессимистично, а не «похоже». Похожесть без файла шаблона не оценить, а цена ошибок
несимметрична: лишняя ступень кегля — косметика, вылезший текст — ошибка аудита и сломанный
слайд на защите.

Почему квартиль, а не самая широкая. Первая версия брала максимум, и на машине разработчика
(923 начертания, 198 подходящих) замена выпала на декоративную DaMiOne — на 50 % шире Arial.
Верхний квартиль там приходится на уровень Verdana / DejaVu Sans. В наборе шрифтов образа
воркера (Liberation, DejaVu, Noto) квартиль даёт **DejaVu Sans** и **DejaVu Sans Bold** — ровно то,
чем fontconfig подменяет неизвестную гарнитуру, так что расчёт совпадает с превью,
по которому работает аудит. В PowerPoint со вшитым Play текст выйдет на ~15 % уже расчёта —
запас, а не дыра.

Результат замера несёт `font_exact: bool`, чтобы вызывающий видел, что считалось по замене.

### `layout/metrics.py` — `measure_text`

* ширины — из `hmtx` через `cmap`, кернинг не учитывается (он почти всегда сужает строку,
  то есть без него расчёт с запасом);
* перенос по словам, как в PowerPoint; слово шире строки рвётся по знакам;
* абзацы — по `\n` и `\v`;
* полезная ширина — рамка минус `TEXT_FRAME_INSET_*` из `domain/units.py`;
* высота — `строк × 1,2 × кегль × line_spacing`.

### `layout/fitting.py` — деградация

`fit_text`: как есть → ступень вниз по `domain.rules.next_size_down` (только шкала шаблона) →
если и на нижней ступени не влезло: `overflow = True` и стратегия для верхнего слоя:

* `shorten` — перебор не больше чем в 1,5 раза или текст из одного абзаца: резать по абзацам нечего;
* `split` — перебор больше и абзацев несколько: слайд делится надвое.

Слой `layout` LLM не вызывает (§3), поэтому сокращение и деление он **назначает**,
а выполняют их композиция и граф.

`fit_block` / `fit_slide`: размер рамки — из блока или плейсхолдера макета, кегль и гарнитура —
из типошкалы роли, **заголовок никогда не уменьшается** (сразу `shorten`).
`fit_slide` возвращает `SlideIR` с заполненным `fit_report` — по нему рендерер (13)
отказывается писать слайд с переполнением.

### `layout/constraints.py` — `solve_positions`

Блоки без плейсхолдера раскладываются kiwisolver'ом: блоки с координатами остаются на месте,
свободные делят равными колонками наибольшую свободную полосу области контента
(`manifest.content_bbox`) с промежутком `grid.gutter_emu`. Ни одной собственной константы
геометрии.

## Проверка

* синтетические шрифты собираются в тестах `fontTools.fontBuilder` с известными ширинами —
  тесты детерминированы и не зависят от шрифтов машины и CI;
* **критерий выхода:** 500 знаков в узкий плейсхолдер → `overflow` в `fit_report` до записи;
* заголовок не уменьшается; кегль берётся только из шкалы шаблона;
* живой прогон: переносы `measure_text` сверяются с числом строк в pdf от LibreOffice.

## Запросы тимлиду

1. **Гарнитура плейсхолдера в манифесте.** Нужно `PlaceholderSpec.font_family: str | None`
   (или `TypographyStep.font_family`) — фактический `<a:latin typeface>` с каскадом
   `slideMaster → slideLayout`. Без него метрики считаются по теме (`Arial`), а текст набран
   Play. На VK-шаблонах Arial и Play по ширине совпадают в пределах 0,5 %, поэтому сейчас это
   не ошибка, а удача: на холодном шаблоне расхождение может быть любым.
   Пользоваться будут: `layout` (метрики), `rendering` (13), аудит (C).
   Туда же — **кегль плейсхолдера** (`PlaceholderSpec.size_pt`): общий кегль роли на VK Education
   даёт 60 pt в полосе заголовка высотой 1,8 см.
2. **`parsing/capacity.py` на настоящие метрики.** Сам заменить не могу: файл тимлида,
   и `parsing` ниже `layout` по слоям — импортировать `layout/metrics` оттуда нельзя.
   Варианты: перенести шрифтовую часть в слой не выше `parsing` или оставить вместимость
   грубой оценкой для планирования, а точность — за `fit_slide`. Предлагаю второе.

## Apply

Реализовано: `layout/{fonts,metrics,fitting,constraints}.py`, API слоя — в `layout/__init__.py`.

Живой прогон поймал баг, которого не видно в рассуждении: **по имени «Arial» находился
Arial Narrow**. У `ARIALN.TTF` типографское семейство (name ID 16) тоже «Arial», а сортировка
по пути ставила его раньше `arial.ttf`. Расчёт занижал число строк в 7 случаях из 10 с Arial.
Теперь начертание другой ширины выбирается, только если его просят по собственному имени.

Слой `layout` импортирует `fontTools` с `# type: ignore[import-untyped]`: у библиотеки нет
типов, а `pyproject.toml` (mypy overrides) — файл тимлида.

**Ревью отдельным агентом** нашло и подтвердило запуском ещё шесть дефектов, все закрыты
тестами до правки:

* висячий пробел в конце абзаца и двойной пробел на месте переноса давали лишнюю пустую
  строку — а значит, лишнюю ступень кегля на ровном месте;
* файл шрифта с целыми `name`/`OS/2`, но испорченными `cmap`/`hmtx` попадал в индекс и ронял
  вёрстку всей колоды; теперь такое начертание пропускается;
* знак, которого нет в шрифте (₽, №), мерился шириной `.notdef` — часто узкой или нулевой;
  теперь — средней шириной буквы гарнитуры;
* закреплённые блоки в разных углах объявляли занятой всю область между ними; теперь ищется
  наибольший свободный прямоугольник, а не полоса вокруг общей рамки;
* нехватка места в решателе вылетала исключением kiwisolver, а не `LayoutFitError`;
* кегль блока вне шкалы шаблона (13 pt при шкале 40/24/18/12) проходил как есть; теперь
  привязывается к ступени ниже.

## Verify

**Тесты:** 60 модульных (`tests/unit/test_layout_{fonts,metrics,fitting,constraints}.py`),
шрифты собираются `fontTools.fontBuilder` прямо в тесте — от шрифтов машины и CI тесты
не зависят. Весь набор — 402 зелёных, ruff и mypy чистые, гейт C6 проходит.

**Переносы против рендера LibreOffice** (текстбоксы pptx → pdf, число строк по координатам
текста в pdf; 180 случаев: кегли 10–32 pt, ширина 3–28 см, 1–3 абзаца, 30 % жирных):

| Гарнитура | Случаев | Совпало | Расчёт на строку больше | Расчёт меньше |
|---|---|---|---|---|
| Arial, Verdana, Times New Roman, Segoe UI, Tahoma, Georgia | 120 | 119 | 1 | **0** |
| Calibri | 20 | 18 | 2 | **0** |
| DejaVu Sans | 20 | 19 | 1 | **0** |
| Play (не установлен, замена) | 20 | 13 | 1 | 6 |

По точным шрифтам — 156 из 160 совпадений, **ни одного занижения**. Шесть занижений у Play —
артефакт машины разработчика: LibreOffice под Windows нашёл по началу имени **Playfair Display
Black** (жирная декоративная гарнитура) и подставил её. В образе воркера Playfair нет,
подстановкой будет DejaVu Sans, и замена `FontLibrary` на том же наборе шрифтов выбирает её же.

**Те же 180 текстбоксов в PowerPoint** (открытие через COM, `TextRange.Lines().Count`):

| Гарнитура | Случаев | Совпало | Расчёт на строку больше | Расчёт меньше |
|---|---|---|---|---|
| Arial, Verdana, Times New Roman, Segoe UI, Tahoma, Georgia | 120 | 119 | 1 | **0** |
| Calibri | 20 | 18 | 2 | **0** |
| DejaVu Sans | 20 | 19 | 1 | **0** |
| Play (не установлен, замена) | 20 | 10 | 10 | **0** |

В PowerPoint замена не занижает ни разу: PowerPoint подставляет вместо Play гарнитуру
скромнее Playfair Display Black, и пессимизм квартиля превращается в запас.

**Колоды pptx-writer (13) в PowerPoint:** на трёх шаблонах кейса по 12 слайдов, текст вписан
`fit_slide` с шрифтами образа воркера — `BoundHeight` текста ни в одной фигуре не превысил
высоту рамки; текст набран Play из шаблона.

**Критерий выхода — выполнен.** Синтетический тест
`test_exit_criterion_500_chars_in_narrow_placeholder_overflow_before_writing` и настоящий шаблон:
500 знаков в самый узкий плейсхолдер тела VK Tech (10,7 × 0,7 см, 12 pt) → `overflow = true`
на нижней ступени 7,8 pt, `strategy = shorten`. Файл не создавался.

**Настоящие шаблоны, шрифты как в образе воркера.** Короткий текст (24 знака) в каждый текстовый
плейсхолдер каждого макета:

| Шаблон | Плейсхолдеров | Влезло | Не влезло |
|---|---|---|---|
| VK Tech | 91 | 67 | 24 заголовка ≈ 11 × 2 см при 24 pt жирным |
| VK WorkSpace | 15 | 15 | — |
| VK Education | 66 | 27 | все 29 заголовков (кегль роли 60 pt), 7 тел, 3 футера 0,67 см |

Время — миллисекунды на слайд; индекс шрифтов строится один раз (≈ 4 с на 923 начертаниях
Windows, в образе воркера шрифтов на порядок меньше).

## Что осталось незакрытым

1. **Манифест не знает гарнитуру и кегль конкретного плейсхолдера** — см. «Запросы тимлиду».
   На VK Education в полосу заголовка высотой 1,8 см ставится общий кегль роли 60 pt, а одна
   строка такого кегля — 2,5 см: переполнение по расчёту есть при любом тексте. Это верный вывод
   из неполных данных, а не ошибка метрик. Большая часть «не влезло» в таблице выше — отсюда,
   и пока полей нет, композиция будет получать `shorten` там, где PowerPoint текст вписал бы.
2. **Отступы буллетов не учитываются**: уровень вложенности и `marL`/`indent` в манифест
   не попадают, буллеты меряются как абзацы на всю ширину. На глубоких уровнях расчёт занижен
   на величину отступа.
3. **Внутренние поля плейсхолдера** (`bodyPr lIns/tIns`) не читаются — берутся поля PowerPoint
   по умолчанию из `domain/units.py`. Шаблон с нестандартными полями даст погрешность.
4. **Интервалы между абзацами** (`spcBef/spcAft`) не учитываются — высота занижена на их сумму.
   Есть ли они в плейсхолдерах тела шаблонов кейса, не проверено.
5. **Точная подстановка для известных гарнитур.** Где есть fontconfig, `fc-match "Arial"`
   даёт метрически совместимый Liberation Sans, а замена `FontLibrary` — квартиль (DejaVu Sans,
   на ~8 % шире). Подключить `fc-match` — небольшая отдельная задача, если пессимизм замены
   начнёт мешать.
6. **`parsing/capacity.py` осталась оценкой** — запрос 2 тимлиду.
7. **Пессимизм замены не измерен в цифрах.** Сколько текстов, признанных переполненными
   по замене, на деле влезли бы в PowerPoint со вшитым Play, — не считалось. На VK Tech заметно,
   что заголовки на 24 pt жирным «не влезают» чаще, чем в реальности.
8. **Замер в образе воркера не выполнен**: podman на машине разработчика нет. Набор шрифтов
   образа воспроизведён копиями Liberation / DejaVu / Noto из системы.
