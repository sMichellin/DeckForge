# by-recipe-is-one-predicate

Таск RG3 зонтичного предложения `recipe-is-not-the-models-word`, бриф 24.09.
Тимлид, файлы `domain/slide.py` и `pipeline/nodes/fit.py`. Приоритет P1, первым из P1:
на него ждут RG4 (поток A) и RG5 (поток B).

Дельта спеки — в зонтичном предложении (требование «Слайд по рецепту — одно условие
на весь пайплайн», capability `slide-composition`); здесь `skip_specs`, чтобы одно
требование не уехало в главную спеку двумя change'ами.

Статус: proposed → applied

## Explore

Пять прогонов 24.09 упали на записи, потому что «слайд по рецепту» понимали тремя
разными способами:

| Слой | Условие | Файл |
|---|---|---|
| вписывание | `slide.recipe_id` | `pipeline/nodes/fit.py:140` |
| проверка перед записью | `slide.recipe_id and block.zone_id` | `rendering/writer.py:207` |
| писатель | `slide.recipe_id in self.recipes` | `rendering/writer.py:494` |

Каждое по отдельности осмысленно. Вместе они дают дыру: вписывание считает слайд
собранным по рецепту и пропускает его, писатель — не собранным и пишет по макету,
а кегль берёт из `fit_report`, которого вписывание не посчитало.

**Два разных вопроса, которые слились в один.** Форма слайда — «рецепт назван и блоки
стоят в зонах» — вопрос к самому `SlideIR`. Существование рецепта — «есть ли `ex005`
в каталоге композиций» — вопрос к дизайн-системе шаблона, и задать его может только тот,
у кого каталог на руках. `domain` о каталоге не знает и знать не должен (ADR-003).
Писатель эти два вопроса смешал в одном условии, и получилось, что на вопрос о форме
он отвечает по наличию рецепта в каталоге.

**Чего этот change не делает.** Слайд `s10` пяти упавших прогонов имел и `recipe_id`,
и `zone_id` у каждого блока — выдумала модель и то и другое. Для него `by_recipe` равен
`true`, и вписывание его по-прежнему пропустит. Это правильно: по форме он слайд по
рецепту, а что рецепт выдуман — видно только из каталога. Ту регрессию закрывает RG1
(`composer-does-not-name-the-recipe`, PR #171): поля каталога снимаются с ответа модели,
и `recipe_id` до `fit` не доезжает.

Здесь закрывается другая дыра того же корня — **слайд с названным рецептом и блоками
вне зон.** Сегодня он достижим: `_split_slide` (`audit/fixes/apply.py:346`) собирает
слайд-продолжение, копируя блоки с их `zone_id`, но `recipe_id` в новый `SlideIR`
не переносит. Обратный случай — `recipe_id` без зон — и был у `s10`. Проверено, что
сегодня продолжение по рецепту не строится: у слайда по рецепту нет блоков-списков
(`bind_to_recipe` отдаёт только `TextBlock`), и `_split_slide` выходит сразу. Дыра
латентная, но лежит ровно там, где уже один раз прорвало.

## Propose

1. **`SlideIR.by_recipe`** — свойство домена: рецепт назван, блоков не ноль, и у каждого
   блока есть `zone_id`. Спрашивается форма, не существование рецепта.
   * Смешанный слайд (часть блоков в зонах, часть нет) — **не** по рецепту: вписать его
     по макету нельзя (блоку в зоне нечего мерить), скопировать пример целиком тоже
     нельзя (блоку вне зоны некуда встать). Такой слайд обязана назвать проверка перед
     записью — это RG5.
   * Слайд без блоков — не по рецепту: `all()` на пустом списке истинен, и без явной
     проверки пустой слайд оказался бы «собранным».
2. **`pipeline/nodes/fit.py`** спрашивает `by_recipe` вместо `recipe_id`.
3. Схемы: `by_recipe` — свойство, не поле, поэтому `python scripts/gen_schemas.py`
   не даёт ни байта диффа. Проверено.

`rendering/writer.py:207` и `:494` переводит на тот же предикат **поток B** (RG5):
файл не наш. В PR RG5 это названо.

## Verify

`tests/unit/test_by_recipe_is_one_predicate.py`, девять тестов.
**С прежним `fit.py`: 2 failed, 7 passed. С правкой: 9 passed.**

Предикат:

| Случай | `by_recipe` |
|---|---|
| рецепт назван, каждый блок в зоне | `true` |
| рецепта нет | `false` |
| рецепт назван, ни одного блока в зоне (форма `s10` до RG1) | `false` |
| рецепт назван, часть блоков в зонах | `false` |
| рецепт назван, блоков нет | `false` |

Вписывание:

* настоящий слайд по рецепту не вписывается — блоки и `fit_report` те же, заметок нет
  (то же, что держал тест `test_a_recipe_slide_is_not_fitted`, он остался зелёным);
* слайд, у которого рецепт только назван, **вписывается**, и кегль посчитан каждому
  блоку — красный до правки;
* параметризованный тест «пропуск вписывания и `by_recipe` — одно решение, а не два
  похожих»: `source.by_recipe is (fitted.fit_report == {})` для обоих значений
  `recipe_id` — красный до правки на `ex003`.

Гейты в образе приложения (`podman`, без сети): `gen_schemas.py` без диффа, `ruff`
passed, `mypy` 140 файлов без замечаний, `lint_no_template_constants.py` OK, полный
`pytest` — **1765 passed, 95 skipped**.

## Что осталось незакрытым

* **Писатель ещё на своих условиях** — RG5, поток B. До него расхождение не закрыто
  целиком: `by_recipe` спрашивают два слоя из трёх.
* **`_split_slide` не переносит `recipe_id`** (`audit/fixes/apply.py:346`) и собирает
  продолжение из блоков с `zone_id`. Сегодня недостижимо, но это заготовка смешанного
  слайда. Файл потока C — запрос владельцу: либо переносить `recipe_id`, либо снимать
  `zone_id` с перенесённых блоков. Тест на смешанный слайд здесь есть, и он описывает,
  что произойдёт.
* **Живой прогон** — RG2, тимлид, после мержа RG1 и этого change'а.
